# 面试流程与策略

::: tip 本篇定位
了解招聘全流程，做好面试前准备和面试后复盘。
:::

## 高频面试题

### Q1：技术面一般考察什么？

**我的答案：**

SRE 岗位的技术面，一般按这个顺序一层层筛人，我心里有数就不会乱。

先是**基础知识深度**：Linux 系统（启动流程、权限、磁盘、进程）、网络（TCP 三次握手、HTTP、排障命令）、一门脚本语言（Shell）。他不是考背书，是看你有没有动手——比如让你说"磁盘满了怎么查"，要能报出 `df -h`、`du -sh /*`、`lsof | grep deleted` 这串真实命令。

第二是**项目真实性**：顺着简历问，让你画架构、讲难点、说你具体干了啥。项目里写的每个技术点他都可能深挖，目的是判断是你真做的还是背的。

第三是**排障思路**：这是 SRE 最核心的。他会抛一个场景，比如"线上接口突然 502"，看你是直接瞎重启，还是按"先看现象和监控 → 再看日志 → 再定位是应用/网络/数据库哪一层 → 恢复后再复盘"这条链路走。思路比答案重要。

第四是**学习能力和沟通**：转行特别看重这个。他会问"这个你不会的东西是怎么自学的"，我会拿我搭家庭实验室、边踩坑边记笔记这件事回答，证明我能自驱补短板。

整体流程上，一般是 HR 初面筛意向和薪资 → 技术一面考基础和项目 → 技术二面/主管面考排障和软实力 → HR 谈 offer。我会在每一轮针对性准备。

### Q2：面试前准备清单？

**我的答案：**

我把准备分成面试前一周、前一天、当天三块，做成 checklist 逐项打勾。

**面试前一周：**

1. 过一遍核心高频题：Linux 启动流程、权限模型、LVM/RAID、进程与 load average、grep/awk/sed/find、TCP/HTTP 基础、Docker 和 K8s 核心对象、监控指标含义。
2. 把项目从头到尾能脱稿讲一遍，并能手动画出架构图；把每个写在简历上的技术点自问自答一遍。
3. 写好 1 分钟和 3 分钟两版自我介绍，对着镜子或录音练到不卡顿。
4. 研究目标公司 JD，把关键词摘出来，确认自己简历和自我介绍里都覆盖了。

**面试前一天：**

1. 准备好反问问题，比如"团队现在值班怎么排""目前最痛的稳定性问题是什么""用的技术栈和规模"。
2. 如果是线上面试，提前测好网络、摄像头、麦克风，开好共享屏幕权限，准备好能随时开终端演示。
3. 查好路线/会议室链接，提前 10 分钟到。

**当天：** 带一份打印简历，把自我介绍在脑子里过一遍，深呼吸。状态比多背两道题更重要。

### Q3：答不上来的问题怎么处理？

**我的答案：**

面试被问住是常态，尤其是转行，我的原则是**诚实 + 展示思路，绝不瞎编**。

具体分三步说。第一，先坦诚："这个点我没有实际用过，不敢乱说。" 千万别硬装，面试官一句追问就露馅，印象分直接归零。

第二，立刻转向讲思路："不过如果让我现在去排查/学，我会这么做——" 比如问我一个没接触过的监控告警系统，我会说"我没用过它，但我用过 Prometheus，思路应该类似：先看它采什么指标、怎么配置告警规则、告警发到哪，我可以照着这个框架去上手"。这体现的是迁移能力和学习方法。

第三，如果是完全没概念的，就大方说"这个确实超出我目前的范围了，我记下来，面试结束后会去补"。面试官不会因为你不会一道题淘汰你，但会因为你胡说八道淘汰你。

记住：SRE 面试看的是你遇到未知问题时的思维方式，不是你背了多少标准答案。

---

### Q4：面试后怎么做复盘？

**我的答案：**

面完不管感觉好坏，当天就做复盘，因为忘得很快。我固定用一张表记四样东西。

第一，**记题目**：把面试官问的每道题写下来，包括当时答得好的和卡住的。尤其是答不上来的那几道，这就是我的知识盲区。

第二，**补答案**：对卡住的题，当场查资料、翻本库，把标准答案补全，整理成笔记。这样一面的收获直接变成下一场的弹药。

第三，**复盘表达**：不光看知识，还要看表达——是不是自我介绍太长了？项目是不是没突出重点？哪一段讲得啰嗦被面试官打断了？下次怎么改。

第四，**记录反馈**：如果面试官给了反馈（哪怕是拒信理由），原样记下，那是最值钱的改进方向。

坚持每场面试都这么复盘，两三场下来高频题就滚瓜烂熟了，状态也会越来越稳。
