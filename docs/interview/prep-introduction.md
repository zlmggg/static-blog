# 自我介绍

::: tip 本篇定位
准备面试开场的自我介绍，突出与岗位匹配的技术和项目。
:::

## 高频面试题

### Q1：怎么做一个高质量的自我介绍？

**我的答案：**

我会准备两版，一版 1 分钟用在电话面和 HR 初面，一版 3 分钟用在技术面现场。核心都是四句话结构：我是谁、我会什么、我做过什么、我为什么来。

**1 分钟版（电话/初面，约 180 字）：**

面试官您好，我叫【姓名】，今年 35 岁，坐标成都，是一名转行的 SRE/运维工程师，系统自学 Linux 与云原生约【1 年半】。我的技术栈围绕一条主线——把服务在 Linux 上稳定跑起来：熟 Linux 系统管理和 TCP/IP 网络排查，容器用 Docker、编排用 Kubernetes v1.30，监控用 Prometheus 3.x 加 Grafana 13。为了把这些练真，我自己搭了一台企业级家庭实验室，双路至强 E5-2686 v4、128G ECC 内存，上面跑过 KVM、用 DevStack 部署过 OpenStack，也搭过 K8s 集群和监控告警。我对稳定性和排障特别有钻劲，希望能把这套手艺用到生产环境。

**3 分钟版（技术面现场，约 450 字）：**

面试官您好，我叫【姓名】，35 岁，东北人，现在定居成都。我之前在【原行业，如传统行业/非 IT 岗位】工作了【N 年】，从【哪一年】开始下定决心转行做 SRE，因为我喜欢"把一台机器从装系统到跑起服务、再出问题能一步步查出来"这种把事情做扎实的感觉。

我的技术能力分三块。第一块是 Linux 和网络：能独立完成装机、初始化、故障排查，熟悉 systemd、磁盘 LVM、进程和性能分析，网络上能用 ping/tcpdump/ss 一条链路定位连通性问题。第二块是云原生：Docker 镜像和 Compose 编排是日常，Kubernetes 我用 v1.30 搭过三节点集群，理解 Deployment/Service/Ingress 这一套对象怎么配合。第三块是可观测：用 Prometheus + Grafana 搭过监控大盘，配过 Alertmanager 告警。

最能代表我的项目是我的家庭实验室云平台。我用一台双路至强 X99 主板、128G ECC 内存的物理机，先做 KVM 虚拟化切分资源，再用 DevStack 单节点部署了 OpenStack 体验计算/网络/存储服务，同时在上面跑了 K8s 集群和监控栈。过程中踩过的坑我都记成了笔记，比如内核参数没调导致容器 OOM、磁盘没做 LVM 后期扩容麻烦——这些让我对"生产环境为什么要这么设计"有了切身体会。

我知道自己是转行，缺大厂线上经验，所以我学习速度快、肯下笨功夫，也愿意从值班、巡检这些基础事做起。非常希望能加入贵团队。

> 替换要点：【姓名】【1 年半】【原行业】【N 年】【哪一年】务必换成真实情况；技术版本号（K8s v1.30、Prometheus 3.x）与本库其他文章保持一致即可，不用改。

### Q2：面试官想通过自我介绍了解什么？

**我的答案：**

面试官听自我介绍，表面是让我开场，实际在暗暗考察四件事，我心里要清楚。

第一是**表达和总结能力**。SRE 要写文档、做复盘、跨团队沟通，说话有没有逻辑、能不能 3 分钟把一件事讲清楚，自我介绍就是第一现场。我故意按"身份—技术栈—项目—意向"的固定结构讲，就是让他听着不累。

第二是**技术和岗位的匹配度**。他边听边对 JD：招的人要会 Linux、会 K8s、会监控，我是不是都提到了？我会把岗位 JD 里出现的关键词，原词嵌进自我介绍里，让他一秒对齐。

第三是**项目的真实性和可追问性**。自我介绍不是背完就完，后面八成会顺着我提到的项目深挖。所以我只讲自己真做过、能画出架构图、能答细节的东西，不吹牛——比如我说搭过 OpenStack，就得准备好被问"DevStack 和生产 OpenStack 差在哪"。

第四是**求职动机和稳定性**。转行 35 岁来面，他一定会关心我为什么转、能不能干长久、会不会干俩月就跑。所以我主动交代转行动机，强调"喜欢把事做扎实"，并表态愿意从基础做起，打消他的顾虑。

一句话总结：自我介绍不是念简历，是主动给他递后面追问的钩子，同时把匹配度和稳定性先立住。
