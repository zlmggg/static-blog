# 行为面试题

::: tip 本篇定位
用 STAR 法则准备"最有成就感、失败、冲突、压力"等行为问题，个人事实处用【】标注替换。
:::

## 高频面试题

### Q1：讲一件你最有成就感的事？（最常考，必背）

**我的答案：**

这道题我用 **STAR 法则**讲，结构是 Situation（背景）→ Task（任务）→ Action（行动）→ Result（结果）。

**S 背景**：我在自学云原生时，光看视频不练手总觉得虚，就决定在自己家里搭一套"迷你生产环境"。硬件是一台双路至强【E5-2686 v4 / X99 主板 / 128G ECC 内存】的物理机，目标是从裸金属一路跑起 KVM 虚拟化、OpenStack 和 K8s 监控栈。

**T 任务**：我要独立完成从装系统、做虚拟化，到上面跑起一整套云平台，并且把踩过的坑都沉淀成文档。

**A 行动**：过程中遇到好几次卡死。比如 OpenStack 用 DevStack 部署一直起不来，我没有瞎重装，而是按排障方法论分层看——先看控制节点日志 `stack.sh.log`，发现是【内核参数没调、容器被 OOM 杀掉】；再查内存和交换分区，定位到是某个服务给的内存配额不合理。我一步步调 `sysctl`、改配置，最后把整套栈跑通了。之后我把整个过程写成了笔记，包括每一步命令和报错原因。

**R 结果**：最终我在这台机器上跑通了 KVM、OpenStack 和一个三节点 K8s 集群，配好了 Prometheus 监控。更重要的是，我不是"会用命令"，而是真正理解了生产环境为什么要做冗余、为什么要调内核参数——这些体会是看书得不到的。

> 替换要点：【】里的硬件型号、具体报错原因换成你真实踩过的坑；Result 里的成果要能被追问细节，讲之前确保每个技术点你都答得上来。

### Q2：讲一次失败或踩坑的经历？

**我的答案：**

这道题面试官不是想看你多惨，而是看你**会不会反思、甩不甩锅**。我用 STAR 讲一个真实的。

**S 背景**：刚搭家庭实验室时，我图省事，磁盘只分了一个区，没做 LVM，日志和系统混在一起。

**T 任务**：后来想扩容、想加数据盘，发现非常被动。

**A 行动**：一开始我还想硬撑着用，结果一次测试把磁盘写满，整个环境起不来。我没有急着重装，而是先 `df -h` 定位写满的分区，用 `du -sh /*` 找到是测试日志堆积，`lsof | grep deleted` 确认没有被占用的句柄后才清理。事后我认真复盘：根因是我一开始规划磁盘时就偷懒，没有按"系统盘、数据盘、日志盘"分开，也没做 LVM 方便后期扩容。

**R 结果**：我把整个环境重建了一遍，这次严格按生产习惯分区、做 LVM、配 logrotate 轮转日志，还专门写了一篇"磁盘规划"的笔记。

我会主动收尾：**这次失败让我真正理解了"为什么生产环境要把数据盘和系统盘分开、为什么要做冗余规划"**——以前这些都是书上的话，踩过坑才变成自己的。

> 替换要点：失败经历一定要选"真实但不致命、且你确实改进了"的，别选能力硬伤；重点放在 Action 里的反思和 Result 里的改进，而不是卖惨。

### Q3：遇到团队冲突或很大压力时你怎么处理？

**我的答案：**

**冲突题**我举一个和"自己较劲"的例子（转行学习阶段最真实）：刚转行时我【35 岁、从零学 Linux】，进度慢，身边有人说"这个年纪别折腾了"，压力很大。我的处理方式不是争辩，而是**把压力拆成每天能完成的小任务**——今天搞懂 systemd，明天搞懂 Nginx，用一个个跑通的实验积累正反馈。遇到和别人意见不合，我习惯先听对方的依据，再拿自己的实验数据说话，而不是争输赢。

**压力题**我这么答：SRE 本身就是 7×24 值班、半夜被告警叫醒的岗位，我对压力有预期。我的方法是**平时把预案做在前面**——告警分级、runbook 写清楚，真出事时照着 SOP 走就不慌；同时做好文档和交接，不把压力全压在自己一个人身上。

我想传达的态度是：**冲突里对事不对人，压力下靠流程和预案而不是靠硬扛**。转行这一年多我能坚持下来，本身就证明了我的抗压和自驱力。

> 替换要点：如果你有真实的职场冲突案例（和同事/和研发的技术分歧），优先换成真实工作经历；【35岁转行】这种背景按真实情况说。

### Q4：HR 面到底在考察什么？

**我的答案：**

我很清楚，技术面过了之后 HR 面不是走过场，她在暗地看四件事。

第一是**稳定性**：我 35 岁转行，她最担心的是我能不能干长久、会不会干俩月觉得难就跑。所以我会主动说清楚——我是认真想清楚才转的，喜欢的就是"把系统搞稳定"这件事，而且定居成都、家庭安顿好了，求的就是一份能长期深耕的工作。

第二是**匹配度和求职诚意**：她会看我对公司了解多少、是不是海投碰运气。所以面试前我一定会做功课，说得出公司业务、这个岗位具体干什么，而不是一句"贵公司很好"。

第三是**沟通协作和价值观**：SRE 要天天跟研发、DBA、网络团队打交道，她通过聊天看我好不好沟通、情绪稳不稳定。

第四是**薪资和到岗时间**：这个后面谈薪专题专门讲。

我的策略是：HR 面态度真诚、信息如实、不夸大不隐瞒。一方面让她对我的稳定性放心（定居成都、想清楚才转行、能长期深耕），另一方面技术面已经证明我能独立负责、能把事做成——把"靠得住、能扛事、可长期"这几个信号一起传达到。
