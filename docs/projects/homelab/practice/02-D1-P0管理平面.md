## 步骤 0 · 开始前检查（3 分钟）

**在哪台**：PVE（root）
**目的**：确认 D0 的成果还在，别在错的地基上盖楼
**开始前**：无

**操作**：

```bash
# 在 PVE 上执行（root）
qm status 9000
pvesm status
systemctl is-active eip.service
ip -4 a show vmbr1 | grep 10.0.0.1
/usr/local/sbin/thin-alert.sh; echo "exit=$?"
```

**应该看到**：
- `status: stopped`（模板不该开机）
- `nvme-lvm` 一行 `active`
- `active`
- `inet 10.0.0.1/24`
- thin-alert 无输出、`exit=0`

**失败怎么办**：
- 模板不存在 → 回 D0 步骤 11
- `nvme-lvm` 不是 active → `vgs` / `pvesm status` 看卷组
- EIP 没起 → `systemctl restart eip.service` 再看

## 步骤 1 · 建 3 台虚拟机（10 分钟）

**在哪台**：PVE（root）
**目的**：从模板 9000 克隆出管理平面三台
**开始前**：步骤 0 全过

**操作**：

1. 建机（**VMID 就是 IP 末位**）：

```bash
# 在 PVE 上执行（root）
bash /root/create-lab-vm.sh 100 2 2048 25
bash /root/create-lab-vm.sh 101 1 1024 15
bash /root/create-lab-vm.sh 102 1 1024 15
```

**应该看到**：每台三行输出，最后是 `完成。首次开机 cloud-init 约需 40-90 秒...` 和 ssh 提示。

2. 等 60 秒，确认三台都在跑：

```bash
# 在 PVE 上执行（root）
qm list | grep -E "lab-(100|101|102)"
```

**应该看到**：三行，状态 `running`。

3. 确认 cloud-init 把 IP 配好了：

```bash
# 在 PVE 上执行（root）
qm guest cmd 100 network-get-interfaces | grep -A2 "ip-address"
ping -c2 10.0.0.100
```

**应该看到**：`10.0.0.100`；ping 通。

**失败怎么办**：
- `模板 9000 不存在` → 回 D0 步骤 11
- `网桥 vmbr1 不存在` → 回 D0 步骤 6
- ping 不通、guest agent 无响应 → 等 2 分钟再试；仍不行 `qm terminal 100` 看启动日志

## 步骤 2 · 给 bastion 发私钥和脚本（5 分钟）

**在哪台**：Windows → PVE → bastion
**目的**：让 bastion 能免密连其他机器，并拿到初始化脚本和 Ansible 清单
**开始前**：步骤 1 的 ping 已通

**操作**：

### 2.1 从 Windows 传到 PVE

```powershell
# 在 Windows PowerShell 里执行
cd ".\ops-project-files"
scp "03-集群部署\p0-node-init.sh" root@192.168.10.30:/root/
scp -r "04-工具与自检\ansible"   root@192.168.10.30:/root/ansible
```

**应该看到**：两次进度条，无报错。

### 2.2 从 PVE 传到 bastion

```bash
# 在 PVE 上执行（root）
scp /root/.ssh/id_ed25519   ubuntu@10.0.0.100:/home/ubuntu/.ssh/id_ed25519
scp /root/p0-node-init.sh   ubuntu@10.0.0.100:/home/ubuntu/
scp -r /root/ansible        ubuntu@10.0.0.100:/home/ubuntu/ansible

ssh ubuntu@10.0.0.100 "chmod 600 ~/.ssh/id_ed25519 && ls -l ~/p0-node-init.sh ~/ansible/inventory.ini"
```

**应该看到**：两个文件都存在，`id_ed25519` 权限 `-rw-------`。

**失败怎么办**：
- `Permission denied` → PVE 的 `/root/.ssh/id_ed25519` 是否存在于 D0 步骤 9.1
- `No such file` → 2.1 没传成功，回 Windows 重传

## 步骤 3 · 三台初始化（5 分钟）

**在哪台**：bastion（ubuntu）
**目的**：统一主机名、写 37 条 hosts、关 IPv6、装基础包
**开始前**：步骤 2 完成

**操作**：

1. 登录 bastion：

```bash
# 在 PVE 上执行（root）
ssh ubuntu@10.0.0.100
```

2. 在 bastion 上跑循环（**一次改三台**）：

```bash
# 在 bastion 上执行（ubuntu）
cd ~
for pair in "10.0.0.100 bastion" "10.0.0.101 ansible-02" "10.0.0.102 ansible-03"; do
  set -- $pair
  scp -q -o StrictHostKeyChecking=no p0-node-init.sh ubuntu@$1:/tmp/
  ssh -o StrictHostKeyChecking=no ubuntu@$1 "sudo bash /tmp/p0-node-init.sh $2"
done
```

**应该看到**：每台最后一行 `初始化完成：<主机名> 10.0.0.x`，以及 `[dns] 跳过` 或 `[dns] 已指向`。

**失败怎么办**：
- 卡在 `cloud-init status --wait` → 正常，等 1–2 分钟
- `Permission denied (publickey)` → 私钥没放对，回步骤 2.2

## 步骤 4 · 内网 DNS（10 分钟）

**在哪台**：bastion（ubuntu）
**目的**：让 `*.lab.local` 在全家都能解析
**开始前**：步骤 3 完成

**操作**：

1. 装 dnsmasq：

```bash
# 在 bastion 上执行（ubuntu）
sudo apt install -y dnsmasq

sudo tee /etc/dnsmasq.d/lab.conf >/dev/null <<'EOF'
domain=lab.local
local=/lab.local/
expand-hosts
listen-address=10.0.0.100
bind-interfaces
server=223.5.5.5
cache-size=1000
EOF

sudo systemctl enable --now dnsmasq
sudo systemctl restart dnsmasq
```

2. 验证解析（此时 hosts 已由步骤 3 写好）：

```bash
# 在 bastion 上执行（ubuntu）
dig +short mysql-01.lab.local @10.0.0.100
dig +short bastion.lab.local @10.0.0.100
```

**应该看到**：`10.0.0.150` 和 `10.0.0.100`（即使 mysql-01 还没建，也能解析）。

3. **再跑一次初始化**，把三台的 DNS 指过来（这次 `[dns]` 会生效）：

```bash
# 在 bastion 上执行（ubuntu）
for pair in "10.0.0.100 bastion" "10.0.0.101 ansible-02" "10.0.0.102 ansible-03"; do
  set -- $pair
  ssh ubuntu@$1 "sudo bash /tmp/p0-node-init.sh $2"
done
```

**应该看到**：每台出现 `[dns] 已指向 10.0.0.100`。

**失败怎么办**：
- `dnsmasq` 起不来 → `sudo systemctl status dnsmasq --no-pager` 和 `ss -lntp | grep :53`，多半是 53 被占
- `dig` 返回空 → `cat /etc/hosts | grep mysql-01` 看 hosts 有没有写进去

## 步骤 5 · 装 Ansible 并验证三节点（10 分钟）

**在哪台**：bastion（ubuntu）
**目的**：主控能批量管三台
**开始前**：步骤 4 的 dig 能通

**操作**：

1. 主控装 Ansible：

```bash
# 在 bastion 上执行（ubuntu）
sudo apt install -y ansible
cd ~/ansible
ansible --version | head -2
```

2. 三节点互相能通 + 跑 ping：

```bash
# 在 bastion 上执行（ubuntu）
ansible ansible -m ping
```

**应该看到**：三台各一段 `"ping": "pong"`，最后 `SUCCESS`。

3. 看主机名和时区（验证批量执行）：

```bash
# 在 bastion 上执行（ubuntu）
ansible ansible -m shell -a 'hostname; timedatectl | head -1'
```

**应该看到**：`bastion` / `ansible-02` / `ansible-03` + `Time zone: Asia/Shanghai`.

**失败怎么办**：
- `UNREACHABLE` → 手工 `ssh ubuntu@10.0.0.101 hostname` 试，不通就是密钥或网络
- `sudo: a password is required` → 本实验 ubuntu 用户免密 sudo，出现这行说明 `/etc/sudoers.d` 被动过
- `command not found: ansible` → 装失败，看 apt 源

## 步骤 6 · 备控同步（5 分钟）

**在哪台**：bastion（root）
**目的**：让 101/102 每 5 分钟从主控同步 playbook 和 inventory，主控挂了能接管
**开始前**：步骤 5 通过

**操作**：

```bash
# 在 bastion 上执行（ubuntu）
sudo apt install -y rsync cron

sudo crontab -l 2>/dev/null | grep -v "ansible-sync" | sudo crontab - 2>/dev/null || true

( sudo crontab -l 2>/dev/null; \
  echo '*/5 * * * * rsync -a --delete -e "ssh -i /home/ubuntu/.ssh/id_ed25519 -o StrictHostKeyChecking=no" /home/ubuntu/ansible/ ubuntu@10.0.0.101:/home/ubuntu/ansible/ && rsync -a --delete -e "ssh -i /home/ubuntu/.ssh/id_ed25519 -o StrictHostKeyChecking=no" /home/ubuntu/ansible/ ubuntu@10.0.0.102:/home/ubuntu/ansible/ # ansible-sync' ) | sudo crontab -
```

**应该看到**：无输出（crontab 写入成功不打印）。

验证：

```bash
# 在 bastion 上执行（ubuntu）
sudo crontab -l
sudo rsync -a --delete -e "ssh -i /home/ubuntu/.ssh/id_ed25519 -o StrictHostKeyChecking=no" ~/ansible/ ubuntu@10.0.0.101:/home/ubuntu/ansible/
ssh ubuntu@10.0.0.101 "ls ~/ansible"
```

**应该看到**：crontab 有一行带 `# ansible-sync`；101 的 `~/ansible` 里也有 `inventory.ini`。

**失败怎么办**：
- `crontab: command not found` → `sudo apt install -y cron`
- rsync 报 `Permission denied` → 101 的 ubuntu 用户目录权限，或密钥没同步
