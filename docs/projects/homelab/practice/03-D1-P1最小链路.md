## 步骤 2 · MySQL（20 分钟）

**在哪台**：mysql-01（10.0.0.150）
**目的**：建库建表，给应用提供数据
**开始前**：步骤 1 的 150 能 ping 通

**操作**：

1. 从 bastion 登录：

```bash
# 在 bastion 上执行（ubuntu）
ssh ubuntu@10.0.0.150
```

2. 装 MySQL 并配置：

```bash
# 在 mysql-01 上执行（ubuntu）
sudo apt install -y mysql-server

sudo tee /etc/mysql/mysql.conf.d/99-lab.cnf >/dev/null <<'EOF'
[mysqld]
bind-address = 0.0.0.0
server-id = 150
gtid_mode = ON
enforce_gtid_consistency = ON
log_bin = mysql-bin
binlog_format = ROW
EOF

sudo systemctl restart mysql
sudo systemctl status mysql --no-pager | head -3
```

**应该看到**：`Active: active (running)`。

3. 建库、建用户、插数据：

```bash
# 在 mysql-01 上执行（ubuntu）
sudo mysql <<'SQL'
CREATE DATABASE IF NOT EXISTS edu CHARACTER SET utf8mb4;
CREATE USER IF NOT EXISTS 'edu'@'10.0.0.%' IDENTIFIED BY '【实验密码】';
GRANT ALL PRIVILEGES ON edu.* TO 'edu'@'10.0.0.%';
FLUSH PRIVILEGES;

USE edu;
CREATE TABLE IF NOT EXISTS course (
  id    INT PRIMARY KEY AUTO_INCREMENT,
  name  VARCHAR(64) NOT NULL,
  price INT NOT NULL
);
INSERT INTO course(name, price) VALUES
  ('Linux 运维', 199), ('K8s 实战', 299), ('MySQL 调优', 259);
SQL
```

4. 验证监听和权限：

```bash
# 在 mysql-01 上执行（ubuntu）
ss -lntp | grep 3306
sudo mysql -e "SELECT COUNT(*) AS courses FROM edu.course;"
```

**应该看到**：`0.0.0.0:3306`；`courses = 3`。

**失败怎么办**：
- `ss` 显示只有 `127.0.0.1:3306` → 99-lab.cnf 没生效，`sudo mysqld --verbose --help | grep bind` 确认，或看 `/etc/mysql/mysql.conf.d/` 是否被 include
- 建用户报错 → 已有同名用户，先 `DROP USER 'edu'@'10.0.0.%';`

## 步骤 5 · Nginx 七层（15 分钟）

**在哪台**：nginx-01（10.0.0.120）、nginx-02（10.0.0.121）
**目的**：把请求转发给 app，并预留蓝绿切换点
**开始前**：步骤 4 的两台 app 都能 curl 通

**操作**：

1. 在 **nginx-01** 上装并配置（121 一样）：

```bash
# 在 nginx-01 上执行（ubuntu）—— 121 换成在 121 上重跑一遍
sudo apt install -y nginx

sudo tee /etc/nginx/conf.d/00-upstream.conf >/dev/null <<'EOF'
upstream app_pool {
    server 10.0.0.130:8080 max_fails=2 fail_timeout=5s;
    server 10.0.0.131:8080 max_fails=2 fail_timeout=5s;
}
EOF

sudo tee /etc/nginx/conf.d/10-server.conf >/dev/null <<'EOF'
server {
    listen 80 default_server;
    server_name _;

    access_log /var/log/nginx/edu-access.log;
    error_log  /var/log/nginx/edu-error.log;

    location = /healthz {
        access_log off;
        return 200 "nginx ok\n";
    }

    location / {
        proxy_pass http://app_pool;
        proxy_set_header Host            $host;
        proxy_set_header X-Real-IP       $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_connect_timeout 2s;
        proxy_read_timeout    10s;
        proxy_next_upstream   error timeout http_502 http_503;
    }
}
EOF

sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
curl -s http://127.0.0.1/healthz
```

**应该看到**：`nginx: configuration file ... test is successful`；`nginx ok`。

2. 在 bastion 上验证两台：

```bash
# 在 bastion 上执行（ubuntu）
curl -s http://10.0.0.120/ | grep 应用节点
curl -s http://10.0.0.121/ | grep 应用节点
```

**应该看到**：返回的 `应用节点` 在 `app-blue-01` / `app-blue-02` 之间随机。

**失败怎么办**：
- `unknown "app_pool"` → 文件名前缀不对，确认是 `00-upstream.conf`（不是 `upstream.conf`）
- 502 → `curl 10.0.0.130:8080/healthz` 通不通；看 `sudo tail -20 /var/log/nginx/edu-error.log`

## 步骤 6 · LVS + keepalived（20 分钟）

**在哪台**：nginx-01/02（RS）+ lvs-01/02（director）
**目的**：四层负载 + VIP 高可用
**开始前**：步骤 5 的两台 Nginx 都能返回页面

**操作**：

### 6.1 两台 Nginx 配 VIP 和 ARP 参数（RS 侧）

```bash
# 在 bastion 上执行（ubuntu）
for ip in 10.0.0.120 10.0.0.121; do
  ssh -o StrictHostKeyChecking=no ubuntu@$ip 'bash -s' <<'EOS'
sudo tee /etc/sysctl.d/99-lvs-rs.conf >/dev/null <<'EOF'
net.ipv4.conf.all.arp_ignore = 1
net.ipv4.conf.all.arp_announce = 2
net.ipv4.conf.lo.arp_ignore = 1
net.ipv4.conf.lo.arp_announce = 2
EOF
sudo sysctl --system >/dev/null

sudo tee /etc/systemd/system/lvs-vip.service >/dev/null <<'EOF'
[Unit]
Description=Add LVS VIP to loopback
After=network-online.target

[Service]
Type=oneshot
ExecStart=-/sbin/ip addr add 10.0.0.119/32 dev lo
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now lvs-vip
ip -4 a show lo | grep 10.0.0.119
EOS
done
```

**应该看到**：两行 `inet 10.0.0.119/32 scope host lo`。

### 6.2 lvs-01 配 keepalived（MASTER）

```bash
# 在 bastion 上执行（ubuntu）
ssh ubuntu@10.0.0.110
```

```bash
# 在 lvs-01 上执行（ubuntu）
sudo apt install -y keepalived ipvsadm
IFACE=$(ip -br link | awk '$1!="lo"{print $1; exit}')
echo "网卡是：$IFACE"

sudo tee /etc/keepalived/keepalived.conf >/dev/null <<EOF
global_defs { router_id LVS_01 }

vrrp_instance VI_1 {
    state MASTER
    interface $IFACE
    virtual_router_id 51
    priority 100
    advert_int 1
    authentication { auth_type PASS; auth_pass lab2026 }
    virtual_ipaddress { 10.0.0.119/24 dev $IFACE }
}

virtual_server 10.0.0.119 80 {
    delay_loop 6
    lb_algo wrr
    lb_kind DR
    persistence_timeout 0
    protocol TCP

    real_server 10.0.0.120 80 {
        weight 1
        TCP_CHECK { connect_timeout 3 nb_get_retry 3 delay_before_retry 3 connect_port 80 }
    }
    real_server 10.0.0.121 80 {
        weight 1
        TCP_CHECK { connect_timeout 3 nb_get_retry 3 delay_before_retry 3 connect_port 80 }
    }
}
EOF

sudo systemctl enable --now keepalived
sleep 2
ip -4 a show $IFACE | grep 10.0.0.119
sudo ipvsadm -Ln
```

**应该看到**：VIP 在本机；`ipvsadm` 里两个 RS 都是 `Route 1 0 0`。

### 6.3 lvs-02 配 keepalived（BACKUP）

```bash
# 在 bastion 上执行（ubuntu）
ssh ubuntu@10.0.0.111
```

```bash
# 在 lvs-02 上执行（ubuntu）
sudo apt install -y keepalived ipvsadm
IFACE=$(ip -br link | awk '$1!="lo"{print $1; exit}')
echo "网卡是：$IFACE"

sudo tee /etc/keepalived/keepalived.conf >/dev/null <<EOF

vrrp_instance VI_1 {
    state BACKUP
    interface $IFACE
    virtual_router_id 51
    priority 90
    advert_int 1
    authentication { auth_type PASS; auth_pass lab2026 }
    virtual_ipaddress { 10.0.0.119/24 dev $IFACE }
}

virtual_server 10.0.0.119 80 {
    delay_loop 6
    lb_algo wrr
    lb_kind DR
    persistence_timeout 0
    protocol TCP

    real_server 10.0.0.120 80 {
        weight 1
        TCP_CHECK { connect_timeout 3 nb_get_retry 3 delay_before_retry 3 connect_port 80 }
    }
    real_server 10.0.0.121 80 {
        weight 1
        TCP_CHECK { connect_timeout 3 nb_get_retry 3 delay_before_retry 3 connect_port 80 }
    }
}
EOF

sudo systemctl enable --now keepalived
ip -4 a show $IFACE | grep 10.0.0.119 || echo "本机无 VIP（正常，备机）"
```

**应该看到**：`本机无 VIP（正常，备机）`。

**失败怎么办**：
- VIP 两台都有（脑裂）→ `journalctl -u keepalived -n 50`；检查 VRRP 组播是否被防火墙拦
- `ipvsadm` 里 RS 是 `Route 0` → 后端 Nginx 没起或 80 不通
- keepalived 起不来 → 配置里 `$IFACE` 是否为空

## 步骤 9 · 故障演练（P1 验收，20 分钟）

**在哪台**：按每条的说明
**目的**：证明你搭的东西真的有高可用

**演练 1：挂一台应用**

```bash
# 在 bastion 上执行（ubuntu）
ssh ubuntu@10.0.0.130 "sudo systemctl stop edu-app"
curl -s http://10.0.0.119/ | grep 应用节点      # 应该只剩 app-blue-02
ssh ubuntu@10.0.0.130 "sudo systemctl start edu-app"
```

**演练 2：挂一台 Nginx**

```bash
# 在 bastion 上执行（ubuntu）
ssh ubuntu@10.0.0.121 "sudo systemctl stop nginx"
sleep 8
curl -s http://10.0.0.119/ | head -3            # 仍可用
ssh ubuntu@10.0.0.110 "sudo ipvsadm -Ln"        # 121 被剔除
ssh ubuntu@10.0.0.121 "sudo systemctl start nginx"
```

**演练 3：挂主 LVS（VIP 漂移）**

```bash
# 在 bastion 上执行（ubuntu）
ssh ubuntu@10.0.0.110 "sudo systemctl stop keepalived"
sleep 3
ssh ubuntu@10.0.0.111 "ip -4 a show | grep 10.0.0.119"   # VIP 已漂移
curl -s http://10.0.0.119/ | grep 版本                    # 仍可用
ssh ubuntu@10.0.0.110 "sudo systemctl start keepalived"
```

**演练 4：挂数据库（预期失败）**

```bash
# 在 bastion 上执行（ubuntu）
ssh ubuntu@10.0.0.150 "sudo systemctl stop mysql"
curl -s http://10.0.0.119/ | grep "数据库连通"   # 会显示 NO
ssh ubuntu@10.0.0.150 "sudo systemctl start mysql"
```

> 第 4 条失败是**故意的**：MySQL 现在是单点，P2 做一主两从后才能演"主库挂了还能读"。
