## 步骤 0 · 开始前检查（3 分钟）

**在哪台**：PVE（root）+ bastion（ubuntu）
**目的**：确认 P1 的数据还在
**开始前**：P1.5 验收通过

**操作**：

```bash
# 在 bastion 上执行（ubuntu）
ssh ubuntu@10.0.0.150 "sudo mysql -e 'SELECT COUNT(*) FROM edu.course;'"
curl -s http://10.0.0.119/ | grep -E "版本|数据库连通"
```

**应该看到**：`3`；`v1`、`数据库连通 YES`。

**失败怎么办**：
- 数据库连不上 → 回 `03-D1-P1最小链路.md` 步骤 2
- 页面 502 → 回 03 步骤 5/6

## 步骤 1 · 建 4 台并初始化（15 分钟）

**在哪台**：PVE（root）建机 → bastion（ubuntu）初始化
**目的**：把两个从库和两个 Redis 节点拉起来
**开始前**：步骤 0 通过

**操作**：

1. 建机（PVE 上）：

```bash
# 在 PVE 上执行（root）
bash /root/create-lab-vm.sh 151 2 3072 30
bash /root/create-lab-vm.sh 152 2 3072 30
bash /root/create-lab-vm.sh 161 1 1536 15
bash /root/create-lab-vm.sh 162 1 1536 15
```

2. 初始化（bastion 上，一次四台）：

```bash
# 在 bastion 上执行（ubuntu）
declare -A M=([151]=mysql-02 [152]=mysql-03 [161]=redis-02 [162]=redis-03)
for id in "${!M[@]}"; do
  h=${M[$id]}
  scp -q -o StrictHostKeyChecking=no ~/p0-node-init.sh ubuntu@10.0.0.$id:/tmp/
  ssh -o StrictHostKeyChecking=no ubuntu@10.0.0.$id "sudo bash /tmp/p0-node-init.sh $h"
done
```

**应该看到**：4 段 `初始化完成：<主机名> 10.0.0.x`。

**失败怎么办**：
- 某台 ping 不通 → `qm terminal <VMID>` 看启动过程

## 步骤 2 · 主库开复制账号（5 分钟）

**在哪台**：mysql-01（10.0.0.150）
**目的**：给从库一个只用于复制的账号
**开始前**：步骤 1 完成

**操作**：

```bash
# 在 bastion 上执行（ubuntu）
ssh ubuntu@10.0.0.150
```

```bash
# 在 mysql-01 上执行（ubuntu）
sudo mysql <<'SQL'
CREATE USER IF NOT EXISTS 'repl'@'10.0.0.%' IDENTIFIED BY '【实验密码】';
GRANT REPLICATION SLAVE ON *.* TO 'repl'@'10.0.0.%';
FLUSH PRIVILEGES;
SELECT user, host FROM mysql.user WHERE user='repl';
SQL
```

**应该看到**：一行 `repl | 10.0.0.%`。

**失败怎么办**：
- `ERROR 1396` → 用户已存在，改成 `ALTER USER` 或先 `DROP USER`

## 步骤 3 · 从库安装与配置（15 分钟）

**在哪台**：mysql-02（151）、mysql-03（152）
**目的**：装 MySQL 并按从库参数配置
**开始前**：步骤 2 完成

**操作**：

```bash
# 在 bastion 上执行（ubuntu）—— 一次配两台，server-id 用 IP 末位
for id in 151 152; do
ssh -o StrictHostKeyChecking=no ubuntu@10.0.0.$id "bash -s" <<EOS
sudo apt install -y mysql-server

sudo tee /etc/mysql/mysql.conf.d/99-lab.cnf >/dev/null <<'EOF'
[mysqld]
server-id = $id
gtid_mode = ON
enforce_gtid_consistency = ON
log_bin = mysql-bin
binlog_format = ROW
relay_log = relay-bin
read_only = ON
EOF

sudo systemctl restart mysql
sudo systemctl is-active mysql
EOS
done
```

**应该看到**：两台各输出 `active`。

**失败怎么办**：
- `active` 变成 `failed` → `sudo journalctl -u mysql -n 30 --no-pager`，多半是配置项写错

## 步骤 4 · 导入数据并建立复制（15 分钟）

**在哪台**：mysql-01（导出）→ bastion（中转）→ 151/152（导入）
**目的**：让从库从主库的同一份数据开始，然后接上复制
**开始前**：步骤 3 的两台从库都是 active

**操作**：

1. 主库导出（带 GTID）：

```bash
# 在 bastion 上执行（ubuntu）
ssh ubuntu@10.0.0.150 "sudo mysqldump --all-databases --single-transaction \
  --set-gtid-purged=ON --routines --triggers > /tmp/all.sql && sudo chmod 644 /tmp/all.sql && ls -lh /tmp/all.sql"
```

**应该看到**：文件几十 KB 到几 MB。

2. 传到两台从库并导入：

```bash
# 在 bastion 上执行（ubuntu）
scp -q ubuntu@10.0.0.150:/tmp/all.sql /tmp/all.sql
for id in 151 152; do
  scp -q /tmp/all.sql ubuntu@10.0.0.$id:/tmp/
  ssh ubuntu@10.0.0.$id "sudo mysql < /tmp/all.sql && sudo mysql -e 'SELECT COUNT(*) FROM edu.course;'"
done
```

**应该看到**：两次 `3`。

3. 在两台上开复制（**二选一，各执行一次**）：

```bash
# 在 bastion 上执行（ubuntu）
for id in 151 152; do
ssh ubuntu@10.0.0.$id "bash -s" <<'EOS'
sudo mysql <<'SQL'
STOP REPLICA;
CHANGE REPLICATION SOURCE TO
  SOURCE_HOST='10.0.0.150',
  SOURCE_USER='repl',
  SOURCE_PASSWORD='【实验密码】',
  SOURCE_AUTO_POSITION=1;
START REPLICA;
SQL
EOS
done
```

**失败怎么办**：
- `ERROR 3021`（已有复制在跑）→ 先 `STOP REPLICA; RESET REPLICA ALL;` 再重来
- `ERROR 1045` → 复制账号密码错，回步骤 2

## 步骤 5 · 验证主从（5 分钟）

**在哪台**：151/152 + 150
**目的**：确认真的在同步
**开始前**：步骤 4 完成

**操作**：

```bash
# 在 bastion 上执行（ubuntu）
for id in 151 152; do
  echo "===== 10.0.0.$id ====="
  ssh ubuntu@10.0.0.$id "sudo mysql -e 'SHOW REPLICA STATUS\G' | grep -E 'Replica_IO_Running|Replica_SQL_Running|Seconds_Behind_Source|Last_Error'"
done
```

**应该看到**：

```
Replica_IO_Running: Yes
Replica_SQL_Running: Yes
Seconds_Behind_Source: 0
```

写一条测试数据，看两台从库是否都收到：

```bash
# 在 bastion 上执行（ubuntu）
ssh ubuntu@10.0.0.150 "sudo mysql -e \"INSERT INTO edu.course(name,price) VALUES('复制的证明',1);\""
sleep 2
for id in 151 152; do ssh ubuntu@10.0.0.$id "sudo mysql -e 'SELECT COUNT(*) FROM edu.course;'"; done
```

**应该看到**：两台都是 `4`。

**失败怎么办**：
- `Replica_SQL_Running: No` → 看 `Last_Error`，删掉那条测试数据后 `START REPLICA`
- `Seconds_Behind_Source` 不为 0 且持续增长 → 网络或从库 CPU 打满

## 步骤 6 · 半同步（可选，5 分钟）

**在哪台**：150 + 151/152
**目的**：至少一个从库确认收到，主库才提交
**开始前**：步骤 5 的异步复制已经是 Yes

**操作**：

```bash
# 在 mysql-01 上执行（ubuntu）
ssh ubuntu@10.0.0.150
```

```bash
# 在 mysql-01 上执行（ubuntu）
sudo mysql <<'SQL'
INSTALL PLUGIN rpl_semi_sync_source SONAME 'semisync_source.so';
SET GLOBAL rpl_semi_sync_source_enabled = ON;
SHOW STATUS LIKE 'Rpl_semi_sync_source_status';
SQL
```

```bash
# 在 bastion 上执行（ubuntu）—— 两台从库各装一次
for id in 151 152; do
ssh ubuntu@10.0.0.$id "bash -s" <<'EOS'
sudo mysql <<'SQL'
INSTALL PLUGIN rpl_semi_sync_replica SONAME 'semisync_replica.so';
SET GLOBAL rpl_semi_sync_replica_enabled = ON;
SHOW STATUS LIKE 'Rpl_semi_sync_replica_status';
SQL
EOS
done
```

**应该看到**：主库 `ON`，从库 `ON`。

> 永久生效要把 `plugin-load-add` / `*_enabled` 写进 `99-lab.cnf` 再重启。
> 如果报 `Can't open shared library`，说明这个版本的插件名不同，执行 `SHOW PLUGINS` 看有没有 `semisync`，没有就跳过这步（异步复制已经能用）。

## 步骤 7 · Redis 主从（10 分钟）

**在哪台**：redis-02（161）、redis-03（162）
**目的**：让两个节点跟随 redis-01
**开始前**：步骤 1 完成

**操作**：

```bash
# 在 bastion 上执行（ubuntu）
for id in 161 162; do
ssh -o StrictHostKeyChecking=no ubuntu@10.0.0.$id "bash -s" <<'EOS'
sudo apt install -y redis-server
sudo sed -i 's/^bind .*/bind 0.0.0.0/' /etc/redis/redis.conf
sudo sed -i 's/^protected-mode .*/protected-mode no/' /etc/redis/redis.conf
echo "replicaof 10.0.0.160 6379" | sudo tee -a /etc/redis/redis.conf >/dev/null
sudo systemctl restart redis-server
sleep 1
redis-cli info replication | grep -E "role|master_link_status"
EOS
done
```

**应该看到**：两台都是 `role:slave`、`master_link_status:up`。

**失败怎么办**：
- `master_link_status:down` → 从节点 `redis-cli -h 10.0.0.160 ping` 是否 PONG
- 配置写重复 → `grep replicaof /etc/redis/redis.conf` 只应有一行

## 步骤 8 · 哨兵（15 分钟）

**在哪台**：160 / 161 / 162 三台
**目的**：主库挂了能自动选新主，应用通过哨兵找到主
**开始前**：步骤 7 的主从是 up

**操作**：

```bash
# 在 bastion 上执行（ubuntu）—— 三台都装哨兵
for id in 160 161 162; do
ssh -o StrictHostKeyChecking=no ubuntu@10.0.0.$id "bash -s" <<'EOS'
sudo tee /etc/redis/sentinel.conf >/dev/null <<'EOF'
port 26379
bind 0.0.0.0
protected-mode no
daemonize no
sentinel monitor mymaster 10.0.0.160 6379 2
sentinel down-after-milliseconds mymaster 5000
sentinel failover-timeout mymaster 60000
sentinel parallel-syncs mymaster 1
EOF
sudo chown redis:redis /etc/redis/sentinel.conf

sudo tee /etc/systemd/system/redis-sentinel.service >/dev/null <<'EOF'
[Unit]
Description=Redis Sentinel
After=network.target

[Service]
User=redis
Group=redis
Type=simple
ExecStart=/usr/bin/redis-server /etc/redis/sentinel.conf --sentinel
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now redis-sentinel
sleep 1
redis-cli -p 26379 sentinel get-master-addr-by-name mymaster
EOS
done
```

**应该看到**：三台都返回两行：

```
10.0.0.160
6379
```

**失败怎么办**：
- `Could not connect` → `systemctl status redis-sentinel --no-pager`
- 返回空 → sentinel.conf 里 `monitor` 那行 IP 写错

## 步骤 9 · 演练：主库挂了（10 分钟）

**在哪台**：bastion
**目的**：证明哨兵能自动切换
**开始前**：步骤 8 三台哨兵都正常

**操作**：

1. 手动触发一次切换（比真宕机温和，适合演练）：

```bash
# 在 bastion 上执行（ubuntu）
ssh ubuntu@10.0.0.160 "redis-cli -p 26379 sentinel failover mymaster"
sleep 8
ssh ubuntu@10.0.0.160 "redis-cli -p 26379 sentinel get-master-addr-by-name mymaster"
```

**应该看到**：master 地址变成了 `10.0.0.161` 或 `10.0.0.162`。

2. 确认老主变成了从：

```bash
# 在 bastion 上执行（ubuntu）
ssh ubuntu@10.0.0.160 "redis-cli info replication | grep -E 'role|master_host'"
```

**应该看到**：`role:slave`，`master_host` 是新主。

3. 看应用的反应（**这一步会失败，是预期的**）：

```bash
# 在 bastion 上执行（ubuntu）
curl -s http://10.0.0.119/ | grep "Redis 访问计数"
```

**应该看到**：`error: ...` —— 因为 P1 的应用是**直连 10.0.0.160** 的，它不知道主库换了。

> 这正是 07 要解决的：新版本应用改成从哨兵取主库地址。切换完 160 会自动变回从节点，整体仍可用。
