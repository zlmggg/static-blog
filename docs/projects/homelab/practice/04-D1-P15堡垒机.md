# 04 · D1-P1.5：堡垒机 JumpServer（1 台）

| 项目 | 内容 |
|---|---|
| **所属阶段** | D1 傍晚 |
| **前置条件** | P1 完成：`http://192.168.10.119` 能打开 |
| **预计耗时** | 40–60 分钟（下载镜像占大半） |
| **完成标志** | 能用 `ops` 账号经 `192.168.10.103:2222` 登录内网机器，**会话记录里能看到回放** |
| **下一步** | P2（MySQL 主从、Redis 哨兵、MinIO/ES） |

**这一步建 1 台：**

| VMID | 主机名 | 角色 | 规格 | EIP |
|---|---|---|---|---|
| 103 | jumpserver | 运维审计入口（PAM） | 4C/8G/50G | 192.168.10.103 |

> 为什么单独加这台：`bastion` 是**机器入口**（Ansible 免密批量），JumpServer 是**人的入口**（录像、授权、审计）。两者分开的原因见 `01-总览与规划/项目架构-文字版.md` 第 4 节第 6 条。

## 步骤 0 · 开始前检查（3 分钟）

**在哪台**：PVE（root）
**目的**：确认内存和磁盘还够
**开始前**：P1 验收通过

**操作**：

```bash
# 在 PVE 上执行（root）
free -g | grep Mem
lvs -o lv_name,data_percent nvme-vg
qm list | grep running | wc -l
```

**应该看到**：`total 125`、可用 ≥ 15G；`data_percent` < 40%；running 台数 13。

**失败怎么办**：
- 可用内存 < 9G → 先关掉暂时不用的 VM（`qm shutdown <VMID>`）
- `data_percent` > 80% → 先清理再装（JumpServer 会占 5–8G）

## 步骤 1 · 建机并初始化（5 分钟）

**在哪台**：PVE（root）建机 → bastion（ubuntu）初始化
**目的**：拉起 103 并统一配置
**开始前**：步骤 0 通过

**操作**：

1. 建机（PVE 上）：

```bash
# 在 PVE 上执行（root）
bash /root/create-lab-vm.sh 103 4 8192 50
qm list | grep lab-103
```

**应该看到**：`lab-103` 一行 `running`。

2. 初始化（bastion 上）：

```bash
# 在 bastion 上执行（ubuntu）
scp -q ~/p0-node-init.sh ubuntu@10.0.0.103:/tmp/
ssh ubuntu@10.0.0.103 "sudo bash /tmp/p0-node-init.sh jumpserver"
```

**应该看到**：`初始化完成：jumpserver 10.0.0.103`。

3. 确认 EIP 已生效：

```powershell
# 在 Windows PowerShell 里执行
Test-NetConnection 192.168.10.103 -Port 22
```

**应该看到**：`TcpTestSucceeded : True`（此时 JumpServer 还没装，只有 SSH 的 22）。

**失败怎么办**：
- EIP 没生效 → `/etc/eip.map` 里有没有 `103`，`systemctl restart eip`
- 内存不足起不来 → `qm shutdown` 别的 VM 再试

---

## 步骤 2 · 安装 JumpServer（30 分钟，主要等下载）

**在哪台**：jumpserver（ubuntu）
**目的**：装 JumpServer v3（自带 Docker 和数据库）
**开始前**：步骤 1 的 103 能 ssh

**操作**：

1. 登录：

```bash
# 在 bastion 上执行（ubuntu）
ssh ubuntu@10.0.0.103
```

2. 下载安装脚本：

```bash
# 在 jumpserver 上执行（ubuntu）
cd /opt
curl -sSL https://resource.fit2cloud.com/jumpserver/jumpserver/release/v3.10.0/quick_start.sh -o quick_start.sh
ls -lh quick_start.sh
```

**应该看到**：文件几十 KB（脚本本身不大，真正的大包在后面下载）。

3. 运行安装（会问几个问题，按下表回答）：

```bash
# 在 jumpserver 上执行（ubuntu）
sudo bash quick_start.sh
```

| 询问 | 回答 |
|---|---|
| 安装目录 | 直接回车（`/opt/jumpserver`） |
| 是否使用外部 MySQL/Redis | **n** |
| 是否使用外部 PostgreSQL | **n** |
| 请输入对外访问的 IP | `10.0.0.103` |
| 是否启用 IPv6 | **n** |
| 是否开始安装 | **y** |

> 这一步会下载 1–2GB 的离线包，国内一般 5–20 分钟。**别中断**，中断了重跑脚本会续传或重来。

4. 启动：

```bash
# 在 jumpserver 上执行（ubuntu）
cd /opt/jumpserver-installer-v3.10.0
sudo ./jmsctl.sh start
sudo ./jmsctl.sh status
```

**应该看到**：`core`、`koko`、`lion`、`magnus`、`chen`、`web` 等容器都是 `Up` 或 `healthy`。

5. 确认端口：

```bash
# 在 jumpserver 上执行（ubuntu）
ss -lntp | grep -E ':(80|2222)\b'
```

**应该看到**：`:80` 和 `:2222` 都在监听。

**失败怎么办**：
- 下载卡住 → `Ctrl+C` 重跑；或先 `curl -I` 测资源站连通性
- 某个容器 `Restarting` → `sudo ./jmsctl.sh logs core`（把 core 换成实际容器名）
- 80 端口被占 → `ss -lntp | grep :80`，停掉占用者（本机默认没有）

## 步骤 3 · 首次登录并改密（5 分钟）

**在哪台**：Windows 浏览器
**目的**：拿到管理后台
**开始前**：步骤 2 的 80 端口在监听

**操作**：

1. 浏览器打开 **<http://192.168.10.103>**
2. 账号 `admin`，密码 `【首次登录密码】`
3. 按提示改成一个你能记住的密码（**记下来**）

**应该看到**：进入 JumpServer 控制台，左侧有"资产管理""用户管理""权限管理""会话审计"。

**失败怎么办**：
- 打不开但 `ss` 显示 80 在听 → Windows 的 EIP 路由，回 D0 步骤 8
- 提示密码错误 → 用 `sudo ./jmsctl.sh reset_admin` 重置（在 installer 目录下）

## 步骤 4 · 加资产和账号（10 分钟）

**在哪台**：JumpServer Web 后台 + PVE
**目的**：让堡垒机知道"有哪些机器可以连"
**开始前**：步骤 3 已登录

**操作**：

1. 先在 PVE 上取出登录 VM 用的私钥（后面粘到 JumpServer）：

```bash
# 在 PVE 上执行（root）
cat /root/.ssh/id_ed25519
```

**应该看到**：`-----BEGIN OPENSSH PRIVATE KEY-----` 开头的一大段。**整段复制**。

2. 在 JumpServer 里建账号（**先建账号，再挂到资产上**）：

菜单：`账号管理` → `账号列表` → `创建`

| 字段 | 值 |
|---|---|
| 名称 | `ubuntu-key` |
| 用户名 | `ubuntu` |
| 类型 | SSH |
| 密钥 | 粘贴上一步复制的私钥 |
| 特权用户 | 不勾 |

3. 建资产：`资产管理` → `资产列表` → `创建`，**逐台建 4 台**：

| 名称 | 地址 | 平台 | 节点 |
|---|---|---|---|
| bastion | 10.0.0.100 | Linux | 默认/接入 |
| lvs-01 | 10.0.0.110 | Linux | 默认/接入 |
| nginx-01 | 10.0.0.120 | Linux | 默认/接入 |
| mysql-01 | 10.0.0.150 | Linux | 默认/数据 |

每台建完后，进入资产详情 → `账号` 标签 → `添加` → 选 `ubuntu-key`。

**应该看到**：4 台资产的状态是"正常"（点"测试连接"能通）。

**失败怎么办**：
- 测试连接失败 → 私钥复制不完整（少了结尾行）；重新复制整段
- 连接超时 → 从 jumpserver 本机 `ssh ubuntu@10.0.0.100` 试，确认网络

## 步骤 5 · 建用户与授权（5 分钟）

**在哪台**：JumpServer Web 后台
**目的**：让"人"有账号，并按最小权限授权
**开始前**：步骤 4 的资产能连通

**操作**：

1. 建用户：`用户管理` → `用户列表` → `创建`

| 用户名 | 姓名 | 角色 | 密码 |
|---|---|---|---|
| ops | 运维 | 系统管理员（或运维员） | 自己设 |
| dev | 开发 | 普通用户 | 自己设 |

2. 建授权：`权限管理` → `资产授权` → `创建`

**授权 1（运维，全量）：**

| 字段 | 值 |
|---|---|
| 名称 | ops-all |
| 用户 | ops |
| 资产 | 全部（4 台） |
| 账号 | 全部 |
| 协议 | ssh |
| 动作 | 全部 |

**授权 2（开发，只读范围）：**

| 字段 | 值 |
|---|---|
| 名称 | dev-readonly |
| 用户 | dev |
| 资产 | nginx-01、bastion |
| 账号 | ubuntu-key |
| 协议 | ssh |

**应该看到**：两条授权记录状态"生效"。

**失败怎么办**：
- 用户登录后看不到资产 → 授权没生效，检查"用户/资产/账号"三项是否都选了
- 角色选错 → 用户详情里改角色后重新登录

## 步骤 6 · 验证 SSH 代理与会话录像（10 分钟）

**在哪台**：Windows PowerShell + JumpServer Web
**目的**：证明"人从这里进、每条命令有记录"
**开始前**：步骤 5 的授权已生效

**操作**：

1. 用 ops 账号走 SSH 代理：

```powershell
# 在 Windows PowerShell 里执行
ssh -p 2222 ops@192.168.10.103
```

2. 按提示输入 ops 的密码，然后会列出可选的资产，输入序号（例如 `1` 是 bastion）。
3. 进去后随便敲两条命令：

```bash
hostname
whoami
exit
```

4. 回到 Web 后台，打开 `会话审计` → `会话记录`，找到刚才那条，点 `回放`。

**应该看到**：能回放出你敲的 `hostname`、`whoami`。

**失败怎么办**：
- `Permission denied` → ops 密码错，或授权没给这台资产
- 连上但没有资产列表 → 授权里的"资产"为空
- 会话记录里没有 → 录像有 1–2 分钟延迟，等一会儿刷新

## 步骤 7 · 收尾

**在哪台**：bastion / PVE
**目的**：把堡垒机的存在接到监控和文档里

**操作**：

1. 把 103 加进 Prometheus（在 prom-01 上）：

```bash
# 在 prom-01 上执行（ubuntu）
sudo sed -i '/10.0.0.191:9100/a\          - 10.0.0.103:9100' /etc/prometheus/prometheus.yml
sudo systemctl restart prometheus
curl -s localhost:9090/api/v1/targets | grep -o '"health":"up"' | wc -l
```

**应该看到**：`14`。

2. 回 PVE 打一个配置快照备份：

```bash
# 在 PVE 上执行（root）
tar czf /root/pve-config-$(date +%F)-p15.tgz /etc/pve /root/.ssh /etc/eip.map 2>/dev/null
ls -lh /root/pve-config-*-p15.tgz
```
