# 12 · P4：K8s 迁移业务

> # ⚠️ 开始之前
>
> **本步要做的是"k8s 迁移业务"。**
> 在动手前，先停下来确认三件事：
>
> 1. P3-3 的蓝绿已经跑通（若依能在 VIP 上正常登录）
> 2. 你知道这次要迁什么：**Nacos 3 个 + 若依 4 个服务**
> 3. 你接受"迁移期间有 5–10 分钟不可用"（实验环境，不做零停机）
>
> 确认后再往下做。

| 项目 | 内容 |
|---|---|
| **所属阶段** | P4 |
| **前置条件** | P3-3 完成；thin 池还有 ≥80G；内存余量 ≥16G |
| **预计耗时** | 3–4 小时（第一次装 K8s 会慢） |
| **完成标志** | `kubectl get nodes` 5 台 Ready；`kubectl get pods` 里 Nacos 3 个 + 若依 4 个 Running；VIP 仍能登录若依 |
| **下一步** | `13-P5-mall-swarm.md` |

## 迁移边界（很重要）

| 组件 | 迁不迁 | 说明 |
|---|---|---|
| Nacos ×3 | **迁** | Docker → StatefulSet |
| gateway / auth / system / file | **迁** | jar → 镜像 → Deployment |
| MySQL | **不迁** | 继续用 10.0.0.150，K8s 里通过 IP 连 |
| Redis | **不迁** | 继续用哨兵 |
| MinIO / ES | **不迁** | 继续用 VM |
| Nginx | **不迁** | 继续做入口，只把 upstream 指向 K8s |

> 这叫"**部分上云**"，是真实企业里最常见的形态——不是所有东西都塞进 K8s。

## 步骤 2 · 装容器运行时和 k8s 组件（25 分钟）

**在哪台**：5 台全部
**目的**：containerd + kubelet/kubeadm/kubectl
**开始前**：步骤 1 的 5 台能 ping 通

**操作**：

```bash
# 在 bastion 上执行（ubuntu）—— 一条命令下发到 5 台
ansible k8s -m shell -a '
set -e
# 1) 关 swap
swapoff -a
sed -i "/\sswap\s/s/^/#/" /etc/fstab

# 2) 内核模块与转发
cat > /etc/modules-load.d/k8s.conf <<EOF
overlay
br_netfilter
EOF
modprobe overlay && modprobe br_netfilter
cat > /etc/sysctl.d/k8s.conf <<EOF
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF
sysctl --system >/dev/null

# 3) containerd
apt-get install -y containerd >/dev/null
mkdir -p /etc/containerd
containerd config default > /etc/containerd/config.toml
sed -i "s/SystemdCgroup = false/SystemdCgroup = true/" /etc/containerd/config.toml
systemctl restart containerd && systemctl enable containerd

# 4) k8s 组件
apt-get install -y apt-transport-https ca-certificates curl gpg >/dev/null
mkdir -p /etc/apt/keyrings
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.30/deb/Release.key | gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
echo "deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.30/deb/ /" \
  > /etc/apt/sources.list.d/kubernetes.list
apt-get update -qq
apt-get install -y kubelet kubeadm kubectl >/dev/null
apt-mark hold kubelet kubeadm kubectl
kubeadm version -o short
' --become
```

**应该看到**：5 行 `v1.30.x`。

**失败怎么办**：
- `pkgs.k8s.io` 访问不了 → 换阿里云镜像源 `https://mirrors.aliyun.com/kubernetes-new/core/stable/v1.30/deb/`
- containerd 起不来 → `journalctl -u containerd -n 30`

## 步骤 3 · 初始化集群（20 分钟）

**在哪台**：k8s-m01（220）初始化 → 其余 4 台加入
**目的**：3 控制平面 + 2 工作节点
**开始前**：步骤 2 的 5 台都有 `kubeadm`

**操作**：

1. 在 m01 上初始化：

```bash
# 在 k8s-m01 上执行（ubuntu）
sudo kubeadm init \
  --apiserver-advertise-address=10.0.0.220 \
  --control-plane-endpoint=10.0.0.220:6443 \
  --pod-network-cidr=10.244.0.0/16 \
  --upload-certs \
  | tee /tmp/kubeadm-init.log
```

**应该看到**：最后有 `Your Kubernetes control-plane has initialized successfully!`，以及两段 join 命令。

2. 配 kubectl：

```bash
# 在 k8s-m01 上执行（ubuntu）
mkdir -p ~/.kube
sudo cp /etc/kubernetes/admin.conf ~/.kube/config
sudo chown ubuntu:ubuntu ~/.kube/config
kubectl get nodes
```

**应该看到**：`k8s-m01   NotReady`（正常，还没装网络插件）。

3. 装 Flannel：

```bash
# 在 k8s-m01 上执行（ubuntu）
kubectl apply -f https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml
sleep 30
kubectl get nodes
kubectl get pods -n kube-flannel
```

**应该看到**：`k8s-m01 Ready`；flannel pod `Running`。

4. 其余 4 台加入（**用第 1 步输出里的命令**，这里给格式）：

```bash
# 在 k8s-m02/m03 上执行（ubuntu）—— 控制平面
sudo kubeadm join 10.0.0.220:6443 --token <实际token> \
  --discovery-token-ca-cert-hash sha256:<实际hash> \
  --control-plane --certificate-key <实际key>
```

```bash
# 在 k8s-w01/w02 上执行（ubuntu）—— 工作节点
sudo kubeadm join 10.0.0.220:6443 --token <实际token> \
  --discovery-token-ca-cert-hash sha256:<实际hash>
```

> 上面的 `<...>` 不是让你照抄，是"把 kubeadm init 输出里的那串粘过来"。
> token 过期了就用 `kubeadm token create --print-join-command` 重新生成。

5. 回到 m01 看结果：

```bash
# 在 k8s-m01 上执行（ubuntu）
kubectl get nodes -o wide
```

**应该看到**：5 台全部 `Ready`。

**失败怎么办**：
- 节点 `NotReady` → `kubectl describe node <名字>` 看 Conditions；多半是 flannel 没起来
- join 报 `x509` → 时间不同步，`timedatectl` 检查
- 加了 control-plane 但 etcd 不健康 → `kubectl get pods -n kube-system`

## 步骤 4 · 让 3 台 master 也能跑 Pod（5 分钟）

**在哪台**：k8s-m01
**目的**：实验只有 2 个 worker，资源不够，允许 master 调度
**开始前**：步骤 3 的 5 台 Ready

**操作**：

```bash
# 在 k8s-m01 上执行（ubuntu）
for n in k8s-m01 k8s-m02 k8s-m03; do
  kubectl taint nodes $n node-role.kubernetes.io/control-plane:NoSchedule- 2>/dev/null || true
done
kubectl get nodes
```

**应该看到**：5 台无 `SchedulingDisabled`。

> 生产里别这么干，这是实验环境的妥协。

## 步骤 5 · 构建若依镜像（30 分钟）

**在哪台**：app-green-02（133，有 jar 和 JDK）
**目的**：把 4 个 jar 打成镜像，导入 5 个节点
**开始前**：步骤 4 完成；133 上 `/opt/ruoyi/*.jar` 还在

**操作**：

1. 在 133 上装 docker 并写 Dockerfile：

```bash
# 在 app-green-02 上执行（ubuntu）
sudo apt install -y docker.io
sudo systemctl enable --now docker

sudo mkdir -p /opt/ruoyi-image
cd /opt/ruoyi-image
sudo tee Dockerfile >/dev/null <<'EOF'
FROM eclipse-temurin:8-jre
WORKDIR /app
COPY app.jar /app/app.jar
ENV JAVA_OPTS="-Xms256m -Xmx512m"
ENTRYPOINT ["sh","-c","java $JAVA_OPTS -jar /app/app.jar"]
EOF
```

2. 逐个构建（4 个镜像）：

```bash
# 在 app-green-02 上执行（ubuntu）
cd /opt/ruoyi-image
for n in gateway auth system file; do
  sudo cp /opt/ruoyi/$n.jar app.jar
  sudo docker build -t ruoyi-$n:v1 . 
done
sudo docker images | grep ruoyi-
```

**应该看到**：4 个 `ruoyi-xxx:v1` 镜像。

3. 导出并分发到 5 个节点：

```bash
# 在 app-green-02 上执行（ubuntu）
cd /opt/ruoyi-image
sudo docker save ruoyi-gateway:v1 ruoyi-auth:v1 ruoyi-system:v1 ruoyi-file:v1 -o ruoyi-images.tar
ls -lh ruoyi-images.tar

for ip in 10.0.0.220 10.0.0.221 10.0.0.222 10.0.0.230 10.0.0.231; do
  scp -q ruoyi-images.tar ubuntu@$ip:/tmp/
  ssh ubuntu@$ip "sudo ctr -n k8s.io images import /tmp/ruoyi-images.tar >/dev/null && echo $ip ok"
done
```

**应该看到**：5 行 `10.0.0.x ok`。

**失败怎么办**：
- `eclipse-temurin:8-jre` 拉不动 → 换 `openjdk:8-jre-slim` 或配镜像加速
- `ctr import` 报错 → 直接 `sudo k3s ctr`？不对，标准是 `ctr -n k8s.io`；检查 containerd 是否在跑

## 步骤 6 · Nacos 上 K8s（25 分钟）

**在哪台**：k8s-m01
**目的**：把 Docker 里的 3 个 Nacos 换成 StatefulSet
**开始前**：步骤 5 的镜像已导入（Nacos 镜像也要导入或直接拉）

**操作**：

1. 先在节点上拉好 Nacos 镜像（或从 130 导出导入）：

```bash
# 在 k8s-m01 上执行（ubuntu）
for ip in 10.0.0.220 10.0.0.221 10.0.0.222 10.0.0.230 10.0.0.231; do
  ssh ubuntu@$ip "sudo ctr -n k8s.io images pull docker.io/nacos/nacos-server:v2.3.2 >/dev/null 2>&1 || true; echo $ip"
done
```

2. 写清单并部署：

```bash
# 在 k8s-m01 上执行（ubuntu）
cat > /tmp/nacos.yaml <<'EOF'
apiVersion: v1
kind: Service
metadata:
  name: nacos-headless
spec:
  clusterIP: None
  selector: { app: nacos }
  ports:
    - { name: http, port: 8848, targetPort: 8848 }
    - { name: grpc, port: 9848, targetPort: 9848 }
---
apiVersion: v1
kind: Service
metadata:
  name: nacos
spec:
  type: NodePort
  selector: { app: nacos }
  ports:
    - { name: http, port: 8848, targetPort: 8848, nodePort: 30848 }
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: nacos
spec:
  serviceName: nacos-headless
  replicas: 3
  selector: { matchLabels: { app: nacos } }
  template:
    metadata: { labels: { app: nacos } }
    spec:
      containers:
        - name: nacos
          image: nacos/nacos-server:v2.3.2
          imagePullPolicy: IfNotPresent
          env:
            - { name: MODE, value: "cluster" }
            - { name: NACOS_SERVERS, value: "nacos-0.nacos-headless:8848 nacos-1.nacos-headless:8848 nacos-2.nacos-headless:8848" }
            - { name: SPRING_DATASOURCE_PLATFORM, value: "mysql" }
            - { name: MYSQL_SERVICE_HOST, value: "10.0.0.150" }
            - { name: MYSQL_SERVICE_DB_NAME, value: "nacos_config" }
            - { name: MYSQL_SERVICE_USER, value: "nacos" }
            - { name: MYSQL_SERVICE_PASSWORD, value: "【实验密码】" }
            - { name: NACOS_AUTH_ENABLE, value: "false" }
            - { name: JVM_XMS, value: "512m" }
            - { name: JVM_XMX, value: "512m" }
          ports:
            - { containerPort: 8848 }
            - { containerPort: 9848 }
          readinessProbe:
            httpGet: { path: /nacos/v1/console/health/readiness, port: 8848 }
            initialDelaySeconds: 30
            periodSeconds: 10
EOF

kubectl apply -f /tmp/nacos.yaml
kubectl get pods -l app=nacos -w
```

**应该看到**：3 个 `nacos-0/1/2` 变成 `Running` 且 `READY 1/1`（按 Ctrl+C 退出 watch）。

3. 验证集群：

```bash
# 在 k8s-m01 上执行（ubuntu）
kubectl exec -it nacos-0 -- curl -s http://localhost:8848/nacos/v1/console/health/readiness; echo
curl -s http://10.0.0.220:30848/nacos/v1/console/health/readiness; echo
```

**应该看到**：两个 `UP`。

**失败怎么办**：
- Pod `CrashLoopBackOff` → `kubectl logs nacos-0`，多半是 MySQL 连不上
- 只有 nacos-0 起来 → 检查 headless service 是否解析：`kubectl run -it --rm dns --image=busybox -- nslookup nacos-headless`

## 步骤 7 · 若依上 K8s（30 分钟）

**在哪台**：k8s-m01
**目的**：4 个服务变成 Deployment
**开始前**：步骤 6 的 Nacos 3 个 Running

**操作**：

```bash
# 在 k8s-m01 上执行（ubuntu）
cat > /tmp/ruoyi.yaml <<'EOF'
apiVersion: apps/v1
kind: Deployment
metadata: { name: ruoyi-gateway }
spec:
  replicas: 1
  selector: { matchLabels: { app: ruoyi-gateway } }
  template:
    metadata: { labels: { app: ruoyi-gateway } }
    spec:
      containers:
        - name: app
          image: ruoyi-gateway:v1
          imagePullPolicy: IfNotPresent
          env:
            - { name: SPRING_PROFILES_ACTIVE, value: "dev" }
            - { name: SPRING_CLOUD_NACOS_SERVER_ADDR, value: "nacos-0.nacos-headless:8848,nacos-1.nacos-headless:8848,nacos-2.nacos-headless:8848" }
          ports: [{ containerPort: 8080 }]
---
apiVersion: v1
kind: Service
metadata: { name: ruoyi-gateway }
spec:
  type: NodePort
  selector: { app: ruoyi-gateway }
  ports: [{ port: 8080, targetPort: 8080, nodePort: 30080 }]
EOF

kubectl apply -f /tmp/ruoyi.yaml
kubectl get pods -l app=ruoyi-gateway
```

其余 3 个服务（auth 9200、system 9201、file 9300）照抄这个模板，改名字、镜像、端口即可。

**应该看到**：4 个 pod 都 `Running`，Nacos 控制台里服务实例指向 K8s 的 Pod IP。

**失败怎么办**：
- `ImagePullBackOff` → 镜像没导入，回步骤 5
- pod `Running` 但 Nacos 里没注册 → `kubectl logs deploy/ruoyi-auth`，看是不是连不上 nacos-headless
