## 本步蓝绿是什么

| | 蓝（blue） | 绿（green） |
|---|---|---|
| 前端 | `/usr/share/nginx/html/ruoyi` | `/usr/share/nginx/html/ruoyi-green` |
| 网关 | 10.0.0.130:8080 | 10.0.0.133:8081 |
| 后端服务 | ← 共用 → | ← 共用 → |

**为什么要说清楚**：真生产的蓝绿是"完整两套应用栈"，这里受 4 台 VM 限制，只做**前端 + 网关**两套，后端 auth/system/file 共用。

**机制完全一样**：改 upstream → `nginx -t` → `reload`，秒级切换、秒级回滚。这个机制练熟了，生产里只是把"绿"的范围扩大。

## 步骤 2 · 起第二个网关（green）（10 分钟）

**在哪台**：app-green-02（133）
**目的**：绿环境有自己的网关，端口 8081
**开始前**：步骤 1 完成

**操作**：

```bash
# 在 app-green-02 上执行（ubuntu）
sudo tee /etc/systemd/system/ruoyi-gateway-green.service >/dev/null <<'EOF'
[Unit]
Description=RuoYi Gateway (green)
After=network-online.target

[Service]
User=ubuntu
WorkingDirectory=/opt/ruoyi
Environment=JAVA_HOME=/opt/jdk8
Environment=SPRING_PROFILES_ACTIVE=dev
Environment=SPRING_CLOUD_NACOS_SERVER_ADDR=10.0.0.130:8848
ExecStart=/opt/jdk8/bin/java -Xms256m -Xmx512m -jar /opt/ruoyi/gateway.jar --server.port=8081
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now ruoyi-gateway-green
sleep 15
sudo systemctl is-active ruoyi-gateway-green
curl -s -o /dev/null -w "%{http_code}\n" http://10.0.0.133:8081/auth/login
```

**应该看到**：`active`；`405`。

> 8081 这个实例也会注册到 Nacos，服务列表里 `ruoyi-gateway` 会变成 2 个实例。
> 后面 P4 迁 K8s 时，这个实例要先停掉。

**失败怎么办**：
- `active` 但 curl 000 → 等 20 秒再试，JVM 启动慢
- 端口占用 → `ss -lntp | grep 8081`

## 步骤 3 · 把 Nginx 改成可切换结构（10 分钟）

**在哪台**：nginx-01/02
**目的**：把 gateway 地址抽成 upstream，把 root 抽成一行，方便 sed 切换
**开始前**：步骤 2 的 8081 返回 405

**操作**：

```bash
# 在 nginx-01 上执行（ubuntu）—— 121 同样执行
sudo tee /etc/nginx/conf.d/ruoyi.conf >/dev/null <<'EOF'
upstream ruoyi_gw {
    server 10.0.0.130:8080;          # BLUE
}

server {
    listen 80 default_server;
    server_name _;

    root /usr/share/nginx/html/ruoyi;   # BLUE
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /prod-api/ {
        proxy_set_header Host $http_host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_pass http://ruoyi_gw/;
    }

    location /es/ {
        proxy_set_header Host $host;
        proxy_pass http://10.0.0.180:9200/;
    }

    location /search/ {
        root /usr/share/nginx/html;
        index index.html;
    }
}
EOF

sudo nginx -t && sudo systemctl reload nginx
curl -s http://127.0.0.1/ | grep -o '<title>[^<]*</title>'
```

**应该看到**：`200`；`<title>若依后台管理系统</title>`（没有 v2）。

**失败怎么办**：
- `nginx -t` 报 upstream 重复定义 → 旧配置里有同名 upstream，删掉旧文件

## 步骤 4 · 切到 green（5 分钟）

**在哪台**：nginx-01/02
**目的**：一次 reload 完成切换
**开始前**：步骤 3 通过

**操作**：

```bash
# 在 nginx-01 上执行（ubuntu）—— 121 同样执行
sudo sed -i 's#server 10.0.0.130:8080;.*#server 10.0.0.133:8081;          # GREEN#' \
  /etc/nginx/conf.d/ruoyi.conf
sudo sed -i 's#root /usr/share/nginx/html/ruoyi;.*#root /usr/share/nginx/html/ruoyi-green;   # GREEN#' \
  /etc/nginx/conf.d/ruoyi.conf
sudo nginx -t && sudo systemctl reload nginx

curl -s http://127.0.0.1/ | grep -o '<title>[^<]*</title>'
curl -s -o /dev/null -w "login=%{http_code}\n" -XPOST http://127.0.0.1/prod-api/auth/login \
  -H 'Content-Type: application/json' -d '{"username":"admin","password":"【实验密码】"}'
```

**应该看到**：`<title>...v2</title>`；`login=200`。

浏览器打开 **<http://192.168.10.119>**，标题变成「若依后台管理系统 v2」，并且**还能正常登录**（说明绿网关把请求转给了共用的后端服务）。

**失败怎么办**：
- 标题变了但登录 502 → 绿网关连不上，`journalctl -u ruoyi-gateway-green -n 50`
- 标题没变 → 浏览器缓存，Ctrl+F5

## 步骤 6 · 金丝雀 10%（可选，5 分钟）

**在哪台**：nginx-01/02
**目的**：先让 10% 用户看到 v2

**操作**：

```bash
# 在 nginx-01 上执行（ubuntu）—— 121 同样执行
sudo tee /etc/nginx/conf.d/ruoyi.conf >/dev/null <<'EOF'
upstream ruoyi_gw {
    server 10.0.0.130:8080 weight=9;   # BLUE 90%
    server 10.0.0.133:8081 weight=1;   # GREEN 10%
}

server {
    listen 80 default_server;
    server_name _;
    root /usr/share/nginx/html/ruoyi;
    index index.html;

    location / { try_files $uri $uri/ /index.html; }

    location /prod-api/ {
        proxy_set_header Host $http_host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_pass http://ruoyi_gw/;
    }

    location /es/ { proxy_set_header Host $host; proxy_pass http://10.0.0.180:9200/; }
    location /search/ { root /usr/share/nginx/html; index index.html; }
}
EOF
sudo nginx -t && sudo systemctl reload nginx

for i in $(seq 20); do curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1/; done | sort | uniq -c
```

**应该看到**：20 次请求基本都 200。**注意**：金丝雀按请求分发，但前端是静态文件（Nginx 本地），upstream 权重只影响 `/prod-api/`，所以"版本差异"看不出来——这正是"前端做金丝雀"的局限。

> 结论：**金丝雀应该做在后端服务上**（比如两套 auth/system 按权重），不是前端。
> 这一步只验证 Nginx 权重语法，生产里要用 Nacos 权重或网关灰度。
