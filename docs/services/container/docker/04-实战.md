> 本篇是 Docker 真正会出事的场景：拉不下镜像、磁盘写满、误删。与 [排障训练场](/cases/) 互链。

## 场景一 · 镜像拉不下来：加速与离线

**为什么需要加速**：默认 `docker pull` 直连 Docker Hub，国内经常超时、TLS 握手失败。registry mirror 相当于在守护进程前挂个中转站，pull 时先问中转站、没有再回源，对用户透明。

**2024 年后的现状（务必知道）**：大厂公共加速器批量关停或限流——USTC、网易已停公共服务，阿里云个人加速器停止同步最新镜像。现在能用的基本是社区中转站，**随时可能挂、有白名单限流、不保证镜像新鲜**，只能当开发环境尽力而为。云厂商内网镜像站只在自家 VPC 内可用。

**生产可用的三条路**：

1. **自建 Harbor proxy cache（推荐）**：把 docker.io/gcr.io/quay.io 缓存到内网，全公司共享，稳定可控，见 [Harbor](/services/container/harbor)。
2. **镜像名前缀替换**：不改 daemon，直接 `docker pull docker.m.daocloud.io/library/nginx:1.27`，拉下来 `docker tag` 回原名。本站统一走轩辕云代理。
3. **离线导入**：有网机器 pull → save 成 tar → 拷到内网 → load。

```bash
# 有网机器
docker pull k8s.m.daocloud.io/pause:3.9
docker tag k8s.m.daocloud.io/pause:3.9 registry.k8s.io/pause:3.9
docker save -o images.tar registry.k8s.io/pause:3.9
# 拷到内网后
docker load -i images.tar
```

::: warning 别把公共加速器写死进生产
公共加速器随时失效。生产 pull 失败第一反应 `docker info` 看 mirrors 是否还通；更稳妥是所有镜像经内网 Harbor 分发，加速器只给开发机。
:::

## 场景二 · 磁盘突然被写满：日志暴涨

**成因**：容器默认日志驱动 json-file，stdout 日志**无限增长**，是生产磁盘写满的头号原因。

**应急**（已发生的）：

```bash
truncate -s 0 $(docker inspect -f '{{.LogPath}}' 容器名)   # 清空当前日志文件
```

**根治**：配日志轮转（见 [02 · daemon.json](./02-部署)），全局 `max-size:100m / max-file:3`，或单容器 `--log-opt max-size=100m --log-opt max-file=3`。注意全局配置只对新建容器生效。

## 场景三 · 清理体系：df 与 prune

```bash
docker system df                       # 看 Docker 占盘概况
docker system df -v                    # 明细
docker system prune                    # 清停止容器+无用网络+悬空镜像（相对安全）
docker system prune -a --volumes       # 连未使用镜像和卷一起清（高危！）
```

::: danger prune -a 慎用
`prune -a --volumes` 会删掉所有没被运行容器引用的镜像和卷。删前 `docker system df -v` 看清，重要镜像提前 push 到 Harbor。误删后得重新下载，卷里的数据可能直接没了。
:::

## 场景四 · 时区与重启策略

- **容器内时间慢 8 小时**：容器默认 UTC。run 加 `-e TZ=Asia/Shanghai`，或挂 `/etc/localtime:/etc/localtime:ro`。
- **`--restart=always` 的坑**：always 连手动 stop 都会拉起；想尊重手动停止用 `unless-stopped`。

## 场景五 · Harbor 私有仓库推拉

公司不可能把镜像传公网，自建 Harbor 做私有仓库。完整推拉：

```bash
docker login harbor.internal.local:80 -u admin
docker tag nginx:1.27 harbor.internal.local:80/library/nginx:1.27
docker push harbor.internal.local:80/library/nginx:1.27
# 别的机器
docker pull harbor.internal.local:80/library/nginx:1.27
```

Harbor 走纯 HTTP 时客户端默认拒绝，要在 daemon.json 配 `insecure-registries`。Harbor 部署与运维详见 [Harbor](/services/container/harbor)。

## 常见问题 FAQ

| 现象 | 原因 | 解法 |
|---|---|---|
| 磁盘突然写满 | 容器 json 日志暴涨 | 配 max-size/max-file；应急 truncate |
| 容器时间慢 8 小时 | 默认 UTC | -e TZ=Asia/Shanghai |
| restart=always 手动停也拉起 | always 无视手动 stop | 改用 unless-stopped |
| push 报 HTTP response to HTTPS client | Harbor 是 HTTP | 配 insecure-registries |
| 误删镜像/容器 | prune -a 乱用 | 删前 df -v 看清，重要镜像 push Harbor |
| 拉镜像超时 | 直连 Docker Hub 不通 | 加速器/前缀替换/离线导入 |

OS 层排查：[df](/commands/storage/df) 看磁盘、[top](/commands/system/top) 看资源、[du](/commands/storage/du) 找大目录。更多套路见 [排障训练场](/cases/)。
