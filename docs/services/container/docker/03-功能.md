# Docker 03 · 功能详解

> 四篇制：[01 理论](./01-理论) · [02 部署](./02-部署) · [03 功能](./03-功能) · [04 实战](./04-实战)
> 本篇是日常使用：镜像怎么管、Dockerfile 怎么写、容器怎么跑、存储网络怎么配。分层/网络原理见 [01 理论](./01-理论)。

## 一、镜像命令

```bash
docker pull nginx:1.27                 # 拉镜像（指定版本，别用 latest）
docker images                          # 看本地镜像
docker history nginx:1.27              # 看镜像分层历史
docker inspect nginx:1.27              # 看镜像详情
docker tag nginx:1.27 harbor.internal.local/library/nginx:1.27   # 打标签
docker rmi nginx:1.27                  # 删镜像
docker image prune                     # 清悬空镜像（安全）
docker save -o nginx.tar nginx:1.27    # 导出离线包
docker load -i nginx.tar               # 导入离线包
```

几个要点：

- **`docker tag` 不复制层**，只是给同一个 IMAGE ID 多起个名字，秒级完成。push 到哪由 tag 的仓库地址前缀决定。
- **`save`/`load` vs `export`/`import`**：save/load 保留历史层和 tag，用于镜像搬家；export/import 不保留层，用于从 rootfs 做基础镜像。多节点共享镜像用 `docker save | ssh 目标 docker load` 管道，不重复下载。
- **删镜像规则**：一个镜像可能被多个 tag 指向，rmi 只是摘标签，摘光才删层；被容器引用的镜像删不掉，要先删容器。
- **悬空镜像（dangling）**：`<none>:<none>`，重新 build 同名镜像后旧 tag 被摘走、层没人要就成了垃圾，`docker image prune` 清理。

## 二、Dockerfile：把构建写成代码

Dockerfile 把"装环境、拷代码、暴露端口、定义启动"写成文本，`docker build` 自动可重复地造镜像。

| 指令 | 作用 | 要点 |
|---|---|---|
| `FROM` | 基础镜像 | 第一条指令；多阶段可写多个 |
| `WORKDIR` | 工作目录 | 后续指令的相对路径基准，不存在自动建 |
| `COPY` | 拷本地文件 | 只支持 build 上下文里的文件 |
| `ADD` | 拷文件（增强） | 自动解压 tar、能下 URL，行为隐式，**优先用 COPY** |
| `RUN` | 构建时执行 | 每条生成一层，多条用 `&&` 合并 |
| `ENV` | 环境变量 | 构建期+运行期都生效 |
| `ARG` | 构建参数 | 只 build 时生效（`--build-arg`） |
| `EXPOSE` | 声明端口 | **只是文档**，发布靠 `-p` |
| `CMD` | 默认启动命令 | run 后面的命令会整体覆盖它 |
| `ENTRYPOINT` | 容器入口 | 不被 run 参数覆盖，常和 CMD 配合 |

CMD 与 ENTRYPOINT 经典配合：

```dockerfile
ENTRYPOINT ["nginx"]
CMD ["-g", "daemon off;"]
# docker run my-nginx      → nginx -g "daemon off;"
# docker run my-nginx -t   → nginx -t（CMD 被替换，ENTRYPOINT 不变）
```

### 多阶段构建（瘦身关键）

```dockerfile
# 构建阶段：带全套编译工具
FROM maven:3.9-eclipse-temurin-21 AS builder
WORKDIR /build
COPY pom.xml .
RUN mvn dependency:go-offline          # 先下依赖，利用层缓存
COPY src ./src
RUN mvn package -DskipTests

# 运行阶段：只拷产物进瘦镜像
FROM eclipse-temurin:21-jre-alpine
WORKDIR /app
COPY --from=builder /build/target/demo.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java","-jar","app.jar"]
```

**原则：编译工具链不进最终镜像**。第一阶段带 Maven+JDK 几百 MB，第二阶段只把 jar 拷进瘦 JRE，最终镜像可能从 800MB 瘦到 170MB。

```bash
docker build -t myapp:1.0 .            # 末尾 . 是 build 上下文
docker build -f deploy/Dockerfile --no-cache -t myapp:1.0 .
```

### 分层缓存四条最佳实践

build 时某层输入没变就复用缓存，**一旦某层失效，它下面所有层全部重建**。由此：

1. **`.dockerignore` 必备**：排除 `.git`、`target/`、`node_modules/`，避免无关文件变动让缓存全失效。
2. **变动少的放上面**：先 `COPY pom.xml` 下依赖，再 `COPY src`——改源码不用重新下依赖。
3. **合并 RUN**：`RUN dnf install -y xxx && dnf clean all`，别一条 RUN 装一个包。
4. **层最小化**：每个 RUN 顺手清缓存，否则临时文件永久带进镜像。

## 三、容器命令

### docker run 参数

```bash
docker run -d --name web01 \
  -p 8080:80 \
  -v /data/web/html:/usr/share/nginx/html \
  -e TZ=Asia/Shanghai \
  --restart=unless-stopped \
  --cpus="1.0" -m="512m" \
  nginx:1.27
```

| 参数 | 作用 |
|---|---|
| `-d` | 后台运行 |
| `-p 宿主:容器` | 端口映射 |
| `-v` | 挂载卷/目录 |
| `-e KEY=VAL` | 环境变量 |
| `--name` | 容器名 |
| `--restart` | 重启策略（no/on-failure/always/unless-stopped） |
| `-it` | 交互+伪终端 |
| `--rm` | 退出后自动删 |

### 生命周期与调试

```bash
docker ps -a                           # 看所有容器
docker start/stop/restart web01        # 启停重启（stop 先 SIGTERM 宽限10s 再 SIGKILL）
docker rm web01                        # 删容器（-f 强删运行中）
docker exec -it web01 /bin/bash        # 进入运行中容器
docker exec web01 ls /etc/nginx        # 不进入直接跑命令
docker logs -f --tail 200 web01        # 跟踪日志
docker stats                           # 实时 CPU/内存/网络
docker cp web01:/etc/nginx/nginx.conf ./   # 容器↔宿主机拷文件
docker inspect -f '{{.NetworkSettings.IPAddress}}' web01   # 取字段
```

## 四、存储：volume 与 bind mount

| | named volume | bind mount |
|---|---|---|
| 位置 | Docker 管理（/var/lib/docker/volumes/） | 用户指定宿主机路径 |
| 适合 | 数据库数据目录 | 开发代码挂载、配置文件 |
| 移植性 | 强 | 弱，依赖宿主机目录 |

```bash
docker volume create pgdata
docker run -d -v pgdata:/var/lib/postgresql/data postgres:17
docker run -d -v /opt/nginx/conf.d:/etc/nginx/conf.d:ro nginx:1.27   # :ro 只读
```

**数据一定要挂出来**，否则容器一删数据全丢。volume 备份用临时容器挂进来打 tar：

```bash
docker run --rm -v pgdata:/volume -v $(pwd):/backup alpine \
  tar czf /backup/pgdata.tar.gz -C /volume .
```

## 五、网络：自建 bridge 用容器名通信

```bash
docker network create mynet
docker run -d --name redis --network mynet redis:7.4
docker run -d --name app --network mynet -e REDIS_HOST=redis myapp:1.0
docker exec app ping -c2 redis         # 容器名直接解析
docker network inspect mynet           # 看网络下的容器和 IP
```

默认 bridge 只能靠 IP 互访，**自建 bridge 自带 DNS**，容器名就能解析——这是 Compose 服务间通信的基础。端口映射四种写法：`-p 8080:80`（所有网卡）、`-p 127.0.0.1:8080:80`（只绑回环）、`-p 80:80/udp`（指定协议）、`-P`（随机高位）。

容器连不通查三步：是不是同一网络？容器名拼对没？目标服务监听的是 `0.0.0.0` 而非 `127.0.0.1`？

## 六、cgroup 资源限制

```bash
docker run -d --cpus="1.0" --memory="512m" --memory-swap="512m" nginx:1.27
docker update --cpus=2 web01           # 运行中动态改
```

底层数据来自 cgroup，`docker stats` 和宿主机 `/sys/fs/cgroup/` 对应目录对得上。`--memory-swap` 不生效见 [02 · swap 报警](./02-部署)。
