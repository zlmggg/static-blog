# Kubernetes 04 · 实战参考

> 四篇制：[01 理论](./01-理论) · [02 部署](./02-部署) · [03 功能](./03-功能) · [04 实战](./04-实战)
> 本篇是 K8s 真正出事时的定位思路。与 [排障训练场](/cases/) 互链。排障核心三件套：`describe` 看 Events、`logs --previous` 看崩溃前日志、`get events` 看集群事件。

## 场景一 · Pod 一直 Pending

Pending = 调度器没给它找到节点。`kubectl describe pod` 看 Events：

- `Insufficient cpu/memory`：节点资源不够，扩容或调小 requests。
- `node(s) had taint ...`：污点没容忍，检查 tolerations。
- `no nodes available`：节点都 NotReady 或被 cordon。

**定位顺序**：describe 看 Events → get nodes 看节点状态 → top nodes 看资源。

## 场景二 · CrashLoopBackOff（反复崩溃重启）

容器起来就退、K8s 反复拉起。**第一步看日志**：

```bash
kubectl logs <pod> --previous        # 看上一次崩溃前的日志（关键）
kubectl describe pod <pod>           # 看 Last State / Exit Code
```

常见原因：启动命令错、配置缺失连不上依赖、健康检查太严、OOMKilled（Exit Code 137，内存超 limits）。`--previous` 是精髓——当前容器可能刚重启没日志，要看崩溃前那次。

## 场景三 · ImagePullBackOff（拉不到镜像）

```bash
kubectl describe pod <pod>           # Events 里有具体拉取错误
```

三类原因：镜像名/tag 写错、私有仓库没配 imagePullSecrets、网络拉不到（国内拉 registry.k8s.io 常失败，用镜像加速或离线导入，见 [Docker 04](/services/container/docker/04-实战)）。

## 场景四 · Node NotReady

节点失联。登上去查：

```bash
systemctl status kubelet             # kubelet 是否挂
journalctl -u kubelet -n 100         # kubelet 日志
systemctl status containerd          # 运行时是否挂
df -h                                # 磁盘是否满（DiskPressure 会驱逐）
```

常见：kubelet 挂、containerd 挂、磁盘满触发驱逐、证书过期。节点压力驱逐见官方文档。

## 场景五 · Service 不通 / Endpoints 为空

```bash
kubectl get endpoints <svc>          # 空 = 没选中 Pod
kubectl get pods --show-labels       # 对比 Service selector 和 Pod label
```

Endpoints 空说明 selector 和 Pod label 对不上，或 Pod 没 Ready（readinessProbe 没过）。这是 Service 不通头号原因。Endpoints 有值但仍不通，查 kube-proxy 和容器内 DNS（`kubectl exec -- nslookup`）。

## 集群巡检顺序

```bash
kubectl get nodes                    # 1. 节点都 Ready？
kubectl get pods -A | grep -v Running   # 2. 有无异常 Pod
kubectl top nodes                    # 3. 资源水位
kubectl get events -A --sort-by=.lastTimestamp | tail   # 4. 最近事件
kubeadm certs check-expiration       # 5. 证书有效期
```

## 证书续期与 etcd 备份

- **证书**：kubeadm 集群证书默认 1 年。`kubeadm certs check-expiration` 看有效期，`kubeadm certs renew all` 续期，续完重启控制面组件。**证书过期是集群突然全挂的隐蔽原因**。
- **etcd 备份**：etcd 是集群命根子，定期快照：

```bash
ETCDCTL_API=3 etcdctl snapshot save /backup/etcd-$(date +%F).db \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key
```

恢复用 `etcdctl snapshot restore`，注意恢复后集群状态回到快照时刻。

## 常见问题 FAQ

| 现象 | 第一步看什么 |
|---|---|
| Pod Pending | describe 的 Events（调度失败原因） |
| CrashLoopBackOff | logs --previous + Exit Code |
| ImagePullBackOff | describe Events 的拉取错误 |
| Node NotReady | 登节点查 kubelet/containerd/磁盘 |
| Service 不通 | get endpoints 是否为空 |
| 集群突然全挂 | 证书是否过期 |

OS 层排查：[systemctl-journalctl](/commands/system/systemctl-journalctl)、[ss](/commands/network/ss)、[top](/commands/system/top)。更多见 [排障训练场](/cases/)。
