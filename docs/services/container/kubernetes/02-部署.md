# Kubernetes 02 · 部署方案

> 四篇制：[01 理论](./01-理论) · [02 部署](./02-部署) · [03 功能](./03-功能) · [04 实战](./04-实战)
> 本篇用 kubeadm 搭一套可用集群。组件架构见 [01 理论](./01-理论)。实验环境用 3 节点（1 控制面 + 2 worker），网段沿用：Pod `10.244.0.0/16`、Service `10.96.0.0/12`。

## 一、环境准备（每个节点）

K8s 对节点环境有硬性要求，先满足再装：

```bash
# 1. 关 swap（kubelet 要求）
sudo swapoff -a
sudo sed -i '/swap/s/^/#/' /etc/fstab

# 2. 加载内核模块 + 网络参数
cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF
sudo modprobe overlay && sudo modprobe br_netfilter
cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF
sudo sysctl --system

# 3. 装容器运行时 containerd（见 Docker 部署），cgroupdriver 用 systemd
sudo mkdir -p /etc/containerd && containerd config default | sudo tee /etc/containerd/config.toml
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
sudo systemctl restart containerd && sudo systemctl enable containerd
```

::: warning 为什么关 swap、为什么 systemd cgroup
kubelet 默认不允许 swap（内存限制会失真）；containerd 的 cgroupdriver 必须和 kubelet 一致用 systemd，否则两套 cgroup 驱动打架、节点不稳。这两点是新手装集群最常踩的坑。
:::

## 二、装 kubeadm/kubelet/kubectl（每个节点）

```bash
# 配置 K8s yum 源（阿里云镜像）后安装
sudo dnf install -y kubelet kubeadm kubectl --disableexcludes=kubernetes
sudo systemctl enable --now kubelet
```

## 三、初始化控制面（仅 master）

```bash
sudo kubeadm init \
  --apiserver-advertise-address=10.0.0.11 \
  --pod-network-cidr=10.244.0.0/16 \
  --service-cidr=10.96.0.0/12 \
  --image-repository=registry.aliyuncs.com/google_containers
```

`--pod-network-cidr` 要和后面 CNI 插件的网段一致（flannel 默认 10.244）。`--image-repository` 用国内镜像避免拉不到控制面镜像。初始化成功后按提示配置 kubectl：

```bash
mkdir -p $HOME/.kube
sudo cp /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config
kubectl get nodes        # 此时 master 是 NotReady，因为还没装 CNI
```

## 四、装 CNI 网络插件

Pod 跨节点通信靠 CNI。装 flannel（简单）或 calico（功能全）：

```bash
kubectl apply -f https://raw.githubusercontent.com/flannel-io/flannel/master/Documentation/kube-flannel.yml
```

装完 CNI 后 master 变 Ready。CoreDNS 也从 Pending 变 Running。

## 五、worker 加入集群

用 init 输出的 join 命令（token 24h 过期，过期用 `kubeadm token create --print-join-command` 重新生成）：

```bash
sudo kubeadm join 10.0.0.11:6443 --token <token> \
  --discovery-token-ca-cert-hash sha256:<hash>
```

```bash
kubectl get nodes -o wide        # 全部 Ready 即集群就绪
kubectl get pods -A              # 系统组件都 Running
```

## 六、节点维护

```bash
kubectl cordon node02            # 标记不可调度（不再接新 Pod）
kubectl drain node02 --ignore-daemonsets --delete-emptydir-data   # 驱逐 Pod 到别处
# 维护完
kubectl uncordon node02          # 恢复可调度
```

**先 cordon 再 drain**：cordon 防止驱逐过程中新 Pod 又调度回来。drain 是节点下线维护的标准动作。
