## 一、kubectl 三类命令

### 查看类

```bash
kubectl get pods -o wide               # Pod 列表（含节点/IP）
kubectl get pods -A                    # 所有命名空间
kubectl describe pod <pod>             # 详情 + Events（排障第一命令）
kubectl logs <pod> [-c 容器] [--previous]   # 日志，多容器要 -c，崩溃看 --previous
kubectl top pods / nodes               # 资源用量（需 metrics-server）
kubectl get events --sort-by=.lastTimestamp   # 最近事件
```

### 操作类

```bash
kubectl apply -f xxx.yaml              # 声明式创建/更新
kubectl delete -f xxx.yaml             # 删除
kubectl scale deploy nginx --replicas=5     # 扩缩容
kubectl set image deploy/nginx nginx=nginx:1.28   # 改镜像发版
kubectl rollout status/history/undo deploy/nginx  # 发布进度/历史/回滚
```

### 调试类

```bash
kubectl exec -it <pod> -- sh           # 进入容器
kubectl exec -it <pod> -- nslookup <svc>    # 容器内测 DNS
kubectl port-forward svc/<svc> 8080:80      # 集群内服务转发到本机调试
kubectl explain pods.spec.containers        # 查 YAML 字段定义（神器）
kubectl api-resources                       # 列所有资源类型
```

`describe` 看 Events、`logs --previous` 看崩溃前日志、`get events` 看集群事件——这三件套是排障主力，详见 [04 实战](./04-实战)。

## 二、核心 YAML 资源

### Deployment + Service（最常用组合）

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 3
  selector:
    matchLabels: { app: web }
  template:
    metadata:
      labels: { app: web }
    spec:
      containers:
        - name: web
          image: nginx:1.27
          ports: [{ containerPort: 80 }]
          resources:
            requests: { cpu: 100m, memory: 128Mi }
            limits: { cpu: 500m, memory: 256Mi }
---
apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  selector: { app: web }
  ports:
    - port: 80
      targetPort: 80
```

**selector 的 label 必须和 Pod 的 label 一致**，否则 Service 选不中 Pod（Endpoints 为空）。resources 的 requests 是调度依据、limits 是上限，不写 limits 可能吃光节点。

### Ingress（七层入口）

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: web
spec:
  rules:
    - host: web.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: web
                port: { number: 80 }
```

Ingress 是集群的七层入口（需装 Ingress Controller，如 ingress-nginx），按域名/路径路由到 Service，相当于集群里的 [Nginx 反向代理](/services/web/nginx/01-理论)。

### ConfigMap 与 Secret

配置与镜像分离：ConfigMap 存普通配置，Secret 存敏感信息（base64，非加密）。用 `envFrom` 或 volume 挂进 Pod，改配置不用重新打镜像。

## 三、扩缩容与滚动发版

```bash
kubectl scale deploy web --replicas=5          # 扩容
kubectl set image deploy/web web=nginx:1.28    # 发版（触发滚动更新）
kubectl rollout status deploy/web              # 看进度
kubectl rollout undo deploy/web                # 回滚上一版
kubectl rollout history deploy/web             # 看历史版本
```

滚动更新时 Deployment 建新 ReplicaSet 逐步起新 Pod、删旧 Pod，保证服务不中断。`maxSurge`/`maxUnavailable` 控制节奏。**镜像 tag 不变 K8s 不会重建 Pod**，发版必须改 tag 或 `kubectl rollout restart`。
