# Nginx 02 · 部署方案

> 四篇制：[01 理论](./01-理论) · [02 部署](./02-部署) · [03 功能](./03-功能) · [04 实战](./04-实战)
> 每个方案按「环境 → 步骤 → 验证」组织，可独立跑通。高可用是跨服务组合，不在本页重复，见文末链接。

**三种方案怎么选**：绝大多数情况用**方案一（包管理）**——发行版仓库或 Nginx 官方源装，升级、卸载、systemd 托管都省心。只有当官方包缺你要的第三方模块、或必须锁死某版本时，才用**方案二（编译安装）**，代价是以后升级要自己重新编译。**方案三（容器化）**适合"配置即代码、环境一致、随编排调度"的场景，本站和 CI/CD 部署都用它。配置文件的层级结构（全局 / events / http / server / location）见 [01 · 配置文件的层级](./01-理论)，下面只看各方案怎么落地。

## 方案一 · 包管理单机（推荐入门）

**环境**：Rocky Linux 9 / Ubuntu 24.04，root 或 sudo 权限，放行 80/443。

### 安装并启动

```bash
# Rocky / CentOS
sudo dnf install -y nginx
sudo systemctl enable --now nginx

# Ubuntu / Debian
sudo apt update && sudo apt install -y nginx
sudo systemctl enable --now nginx
```

### 验证

```bash
curl -I http://127.0.0.1        # 期望 HTTP/1.1 200 OK
ss -lntp | grep ':80'           # 确认 nginx 在监听
systemctl status nginx --no-pager
```

### 目录结构（两套发行版略有差异）

| 路径 | 作用 |
|---|---|
| `/etc/nginx/nginx.conf` | 主配置：全局块 + events + http |
| `/etc/nginx/conf.d/*.conf` | Rocky 系站点配置目录 |
| `/etc/nginx/sites-available/` + `sites-enabled/` | Ubuntu 系：可用站点 + 软链启用 |
| `/var/log/nginx/` | access.log / error.log |
| `/usr/share/nginx/html` | 默认静态根目录 |

### 最小站点配置

一个能跑的静态站只需要这几行：`listen` 定端口、`server_name` 定域名、`root` 定文件目录、`location /` 用 `try_files` 兜底。`try_files $uri $uri/ =404` 的意思是"先找同名文件、再找同名目录、都没有就 404"，这是静态站的标准写法（SPA 的兜底写法见 [04 · 场景二](./04-实战)）。

```nginx
# /etc/nginx/conf.d/site.conf
server {
    listen 80;
    server_name example.com;
    root /var/www/site;
    index index.html;

    location / {
        try_files $uri $uri/ =404;
    }
}
```

### 放行防火墙并加载

```bash
# Rocky
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --reload
# Ubuntu
sudo ufw allow 'Nginx Full'

sudo nginx -t && sudo systemctl reload nginx
```

## 方案二 · 编译安装（需要第三方模块时）

**何时选**：官方包没有你要的模块（如 `ngx_cache_purge`），或必须锁定某个版本。否则优先方案一。

### 依赖与编译

```bash
sudo dnf groupinstall -y 'Development Tools'
sudo dnf install -y pcre-devel zlib-devel openssl-devel

tar xf nginx-1.26.2.tar.gz && cd nginx-1.26.2
./configure --prefix=/usr/local/nginx \
  --with-http_ssl_module --with-http_v2_module \
  --with-http_stub_status_module
make -j$(nproc) && sudo make install
```

### systemd 单元

```ini
# /etc/systemd/system/nginx.service
[Unit]
Description=nginx (compiled)
After=network.target

[Service]
Type=forking
ExecStartPre=/usr/local/nginx/sbin/nginx -t
ExecStart=/usr/local/nginx/sbin/nginx
ExecReload=/usr/local/nginx/sbin/nginx -s reload
ExecStop=/usr/local/nginx/sbin/nginx -s quit

[Install]
WantedBy=multi-user.target
```

### 验证

```bash
sudo systemctl daemon-reload && sudo systemctl enable --now nginx
/usr/local/nginx/sbin/nginx -V   # 查看版本与已编译模块
```

## 方案三 · 容器化

**为什么容器化**：把 Nginx 和它的配置、静态文件一起打包成镜像，环境完全一致、可随编排调度、升级就是换镜像 tag。关键原则是**容器无状态**——配置、静态文件、日志都用 volume 挂到宿主机，容器本身随时可删可重建。下面 `docker run` 和 compose 两种写法等价，compose 更适合纳入版本管理。

### docker run

```bash
docker run -d --name nginx --restart unless-stopped \
  -p 80:80 -p 443:443 \
  -v /opt/nginx/conf.d:/etc/nginx/conf.d:ro \
  -v /opt/nginx/html:/usr/share/nginx/html:ro \
  -v /opt/nginx/logs:/var/log/nginx \
  nginx:stable
```

### docker-compose.yml

```yaml
services:
  nginx:
    image: nginx:stable
    ports: ["80:80", "443:443"]
    volumes:
      - ./conf.d:/etc/nginx/conf.d:ro
      - ./html:/usr/share/nginx/html:ro
      - ./logs:/var/log/nginx
    restart: unless-stopped
```

::: tip 容器化两个必做
改配置后热加载：`docker exec nginx nginx -t && docker exec nginx nginx -s reload`。
配置与日志一定挂出来，否则容器一删全丢。镜像拉取统一走轩辕云代理。
:::
