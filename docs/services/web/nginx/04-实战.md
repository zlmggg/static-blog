## 场景一 · 反向代理 API（含 WebSocket）

**要解决什么**：前端调 `/api/` 走后端，同时 `/ws/` 要建 WebSocket 长连接。普通反代配几个请求头即可（原理见 [03 · 反代请求头](./03-功能)），但 WebSocket 不一样——它 starts as 一个普通 HTTP 请求，靠 `Upgrade: websocket` + `Connection: Upgrade` 这两个头"升级"成持久双向连接。Nginx 默认用 HTTP/1.0 连后端、会丢掉这两个头，所以必须显式升到 1.1 并把升级头透传过去。下面用 `map` 根据请求是否带 `Upgrade` 动态决定 `Connection` 的值（有升级请求就 upgrade，普通请求就 close），一套配置同时兼容两种流量。`proxy_read_timeout 3600s` 是因为 WebSocket 可能长时间没数据，默认 60s 会把空闲连接掐断。

```nginx
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}
server {
    listen 80;
    location /api/ {
        proxy_pass http://backend;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
    location /ws/ {
        proxy_pass http://backend;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_read_timeout 3600s;
    }
}
```

## 场景二 · 静态站 + SPA 前端

**要解决什么**：Vue/React 单页应用（SPA）用前端路由（history 模式），URL 如 `/user/123` 在磁盘上**并没有对应文件**——它只是前端 JS 里的一个路由。如果 Nginx 按静态文件去找，必然 404。解法是 `try_files $uri $uri/ /index.html`：先找真实文件，找不到就**兜底返回 index.html**，让前端 JS 接管路由。而 `/assets/` 下是带哈希的打包产物，内容不变文件名就不变，可以放心强缓存 30 天。本站正是这种静态托管。

```nginx
server {
    listen 80;
    root /var/www/spa;
    location / { try_files $uri $uri/ /index.html; }
    location /assets/ { expires 30d; add_header Cache-Control "public"; }
}
```

本站就是这种静态托管，见 [禾光知寒站点](/projects/site-blog)。

## 场景三 · 限流防刷

**要解决什么**：防止单个 IP 高频刷接口拖垮后端。`limit_req` 用的是**漏桶算法**：`rate=10r/s` 定义桶的"漏出速度"（平均每秒放行 10 个），`burst=20` 是桶的容量（允许瞬时攒下 20 个突发请求排队），`nodelay` 表示突发请求不排队等待、立刻处理但占用桶额度。三者配合的效果是"长期平均不超过 10r/s，但允许短时突发"。`$binary_remote_addr` 按客户端 IP 计数（二进制形式比字符串省内存），`zone=perip:10m` 开辟 10MB 共享内存存计数状态。超额的请求默认返回 503。

```nginx
limit_req_zone $binary_remote_addr zone=perip:10m rate=10r/s;
server {
    location /api/ {
        limit_req zone=perip burst=20 nodelay;
        proxy_pass http://backend;
    }
}
```

## 场景四 · HTTPS 与跳转

**要解决什么**：在 Nginx 这层统一卸载 TLS（后端走明文 HTTP，证书只在一处管），并强制全站 HTTPS。443 的 server 挂证书、开 http2、加 HSTS 头（`Strict-Transport-Security` 告诉浏览器"以后一年内都直接用 https 访问我"，防降级攻击）；80 的 server 用 `return 301` 把明文请求永久跳转到 https。`$host$request_uri` 保证跳转后域名和路径参数原样保留。

```nginx
server {
    listen 443 ssl;
    http2 on;
    server_name example.com;
    ssl_certificate     /etc/nginx/ssl/example.com.pem;
    ssl_certificate_key /etc/nginx/ssl/example.com.key;
    add_header Strict-Transport-Security "max-age=31536000" always;
    location / { proxy_pass http://backend; }
}
server {
    listen 80;
    server_name example.com;
    return 301 https://$host$request_uri;
}
```

证书申请与校验用 openssl（`openssl s_client -connect example.com:443` 验证握手），文档见 <https://www.openssl.org/docs/man3.0/man1/openssl.html>。

| 症状 | 第一反应 | 深入 |
|---|---|---|
| 502 Bad Gateway | 后端没起 / 端口错 / upstream 写错 | [排障案例 · Nginx 502](/cases/t-nginx-502) |
| 504 Gateway Timeout | 后端慢，read_timeout 到了 | [排障案例 · Nginx 504](/cases/t-nginx-504-timeout) |
