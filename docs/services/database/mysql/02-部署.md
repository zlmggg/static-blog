# MySQL 02 · 部署方案

> 四篇制：[01 理论](./01-理论) · [02 部署](./02-部署) · [03 功能](./03-功能) · [04 实战](./04-实战)

## 方案一 · 包管理单机（推荐入门）

**环境**：Rocky Linux 9 / Ubuntu 24.04，root 或 sudo，放行 3306（生产建议只对应用网段开放，不要公网裸奔）。

### 安装并启动

```bash
# Rocky / CentOS —— 官方 MySQL 8.0 源
sudo dnf install -y https://dev.mysql.com/get/mysql80-community-release-el9-1.noarch.rpm
sudo dnf install -y mysql-community-server
sudo systemctl enable --now mysqld

# Rocky / CentOS —— MariaDB（本站实验环境方案）
sudo dnf install -y mariadb-server
sudo systemctl enable --now mariadb

# Debian / Ubuntu
sudo apt update && sudo apt install -y mariadb-server   # 或 mysql-server
sudo systemctl enable --now mariadb
```

MySQL 8.0 首次启动会在日志里生成一个**随机临时密码**，必须先拿到它才能登录：

```bash
sudo grep 'temporary password' /var/log/mysqld.log
# [Note] A temporary password is generated for root@localhost: xj?k9!pQ...
```

MariaDB 本机 root 常为空密码（走 unix_socket 认证），直接 `sudo mysql` 即可进。

### 安全初始化（必做）

```bash
sudo mysql_secure_installation
```

按提示逐项完成，每一步都有明确的安全意义：

1. 输入 root 当前密码（MySQL 用临时密码；MariaDB 本机常为空，回车）；
2. 设置 root 密码 / 切换 unix_socket 认证；
3. **删除匿名用户**（匿名账号是历史遗留的后门）；
4. **禁止 root 远程登录**（root 只在本机，远程用普通账号）；
5. **删除 test 测试库**（默认任何人可写，是隐患）；
6. **刷新权限表**。

### 验证

```bash
sudo mysql -u root -p                 # 本机登录
mysql -h 10.0.0.13 -P 3306 -u app -p  # 远程登录
```

```sql
SELECT VERSION(), USER(), NOW();
SHOW DATABASES;
```

::: warning MySQL 8.0 认证插件坑
8.0 默认认证插件是 `caching_sha2_password`，老版本 Navicat 等客户端可能连不上。可对某用户改回旧插件：
```sql
ALTER USER 'app'@'%' IDENTIFIED WITH mysql_native_password BY 'App@123';
FLUSH PRIVILEGES;
```
更好的做法是升级客户端，而不是全局降级认证。
:::

## 方案二 · 二进制包（版本可控，生产常用）

**何时选**：要锁定精确小版本、或发行版仓库版本太旧时。从 <https://dev.mysql.com/downloads/mysql/> 下载 Linux-Generic 包：

```bash
tar -xJf mysql-8.0.42-linux-glibc2.17-x86_64.tar.xz -C /usr/local/
ln -s /usr/local/mysql-8.0.42-linux-glibc2.17-x86_64 /usr/local/mysql
groupadd mysql && useradd -r -g mysql -s /sbin/nologin mysql
cd /usr/local/mysql
mkdir mysql-files && chown mysql:mysql mysql-files
bin/mysqld --initialize --user=mysql        # 初始化，末尾打印 root 临时密码
cp support-files/mysql.server /etc/init.d/mysql
```

`--initialize` 会创建系统表并生成临时密码；用软链 `/usr/local/mysql` 指向具体版本目录，以后升级只需换软链，路径不变。

## 方案三 · 容器化（版本锁定）

```bash
docker run -d --name mysql \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD='请替换为强密码' \
  -v /data/mysql:/var/lib/mysql \
  mysql:8.0.42

# MariaDB（本站锁定版本）
docker run -d --name mariadb \
  -p 3306:3306 \
  -e MARIADB_ROOT_PASSWORD='请替换为强密码' \
  -v /data/mysql:/var/lib/mysql \
  mariadb:11.4.13
```

::: tip 容器化必做
**数据目录一定挂出来**（`-v /data/mysql:/var/lib/mysql`），否则容器一删数据全丢。密码用环境变量或 secret 注入，不要写死在镜像里。镜像拉取统一走轩辕云代理。
:::

## 方案四 · 主从复制（高可用的地基）

单机扛不住读压力、也没有冗余，第一步扩展就是**一主一从**。原理是三个线程接力（详见 [01 · 日志体系](./01-理论)）：

```text
主库：写 binlog；binlog dump 线程把变更推给从库
从库 IO 线程：拉取 binlog 写入 relay log
从库 SQL 线程：读取 relay log 重放
```

### 传统位点方式

**主库 my.cnf：**

```ini
[mysqld]
server-id=1
log-bin=mysql-bin
binlog_format=row
```

```sql
CREATE USER 'repl'@'10.0.0.%' IDENTIFIED BY 'Repl@123';
GRANT REPLICATION SLAVE ON *.* TO 'repl'@'10.0.0.%';
SHOW MASTER STATUS;   -- 记下 File 和 Position
```

**从库**（server-id 必须与主不同）：

```sql
CHANGE MASTER TO
  MASTER_HOST='10.0.0.13', MASTER_PORT=3306,
  MASTER_USER='repl', MASTER_PASSWORD='Repl@123',
  MASTER_LOG_FILE='mysql-bin.000001', MASTER_LOG_POS=156;
START SLAVE;
SHOW SLAVE STATUS\G
-- 关键看：Slave_IO_Running=Yes、Slave_SQL_Running=Yes、Seconds_Behind_Master
```

### GTID 方式（推荐）

传统位点要手工对 File/Position，切换时容易错。**GTID** 给每个事务分配全局唯一 ID，从库自动找位点，切换简单可靠：

```ini
gtid_mode=ON
enforce_gtid_consistency=ON
log_slave_updates=ON
```

```sql
CHANGE MASTER TO MASTER_HOST='10.0.0.13', MASTER_USER='repl',
  MASTER_PASSWORD='Repl@123', MASTER_AUTO_POSITION=1;
START SLAVE;
```

### 半同步复制

默认**异步**复制：主库写完 binlog 就返回，不等从库——主库宕机可能丢最后几个事务。**半同步**让主库至少等一个从库确认收到 binlog 才返回（插件 `rpl_semi_sync_master/slave`），更安全；超时会自动退化为异步，不会卡死业务。

### 验证与常见复制问题

| 现象 | 处理方向 |
|---|---|
| IO/SQL 线程 No | 看 Last_IO_Error/Last_SQL_Error；网络、账号、位点 |
| 1062 主键冲突 / 1236 找不到日志 | 核对位点/GTID，手动跳过或重建从库 |
| 主从延迟大 | 大事务拆分、从库性能、开并行复制（slave_parallel_workers） |
| 数据不一致 | pt-table-checksum 校验、pt-table-sync 修复 |

## 高可用方案选型

一主一从只是地基，主库挂了还要有人自动顶上。各方案定位：

| 方案 | 说明 | 适用 |
|---|---|---|
| MHA | Manager+Node：主故障选数据最新的从、补 binlog、提升新主、重定向其他从 | 经典自动切换 |
| **MGR** | 官方组复制，基于 Paxos，单主/多主，成员自动协调、故障自动切换 | 官方方案首选 |
| InnoDB Cluster | MGR + MySQL Router + Shell 的官方完整套件 | 想要官方全家桶 |
| Galera / PXC | 同步多主写、强一致 | 需要多写 |
| Orchestrator | 拓扑管理 + 自动故障切换 | 配合 ProxySQL |

**故障切换的通用流程**：检测主故障 → 选数据最新的从（位点/GTID 最高）→ 提升为新主 → 其他从改指新主 → VIP/路由切换 → 应用恢复。

::: tip 选型建议
个人/小项目：一主一从 + 备份 + 脚本切换就够；要自动高可用：MGR 或 Orchestrator + ProxySQL；云上：直接用 RDS，自带高可用，成本换省心。完整的"主从+读写分离"组合落地见 [部署方案](/deploy/) 与 [我的项目 · 项目架构](/projects/homelab)。
:::
