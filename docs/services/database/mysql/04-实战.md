## 场景一 · 备份与恢复（最重要的运维动作）

**为什么备份是第一优先级**：数据库是业务的命根子，误删、宕机、勒索都可能让数据归零。**能恢复的备份才算有效备份**——没做过恢复演练的备份等于没有。备份分逻辑（导出 SQL）和物理（拷贝数据文件）两类。

### mysqldump（逻辑备份，中小库）

```bash
# 一致性热备 + 记录 binlog 位点 + 含存储过程/触发器/事件
mysqldump -u root -p --single-transaction --source-data=2 \
  --routines --triggers --events -A > all.sql

# 恢复
mysql -u root -p appdb < appdb.sql
```

`--single-transaction` 为什么能保证 InnoDB 一致性？因为它在备份开始时开一个 RR 事务，利用 MVCC 读快照（见 [01 · MVCC](./01-理论)），整个备份过程看到的是同一时刻的数据，且不锁表。`--source-data=2` 把 binlog 位点记成注释，供后续 PITR 用。

### XtraBackup（物理热备，大库）

逻辑备份恢复要重放 SQL，大库很慢；物理备份直接拷文件，恢复快得多：

```bash
xtrabackup --backup --user=root --password=x --target-dir=/backup/full
xtrabackup --prepare --target-dir=/backup/full          # 应用 redo 让数据一致
# 停库、清空数据目录后：
xtrabackup --copy-back --target-dir=/backup/full
chown -R mysql:mysql /var/lib/mysql
```

`--prepare` 是关键：备份期间数据页可能不一致，prepare 用 redo log 前滚、undo 回滚，把备份整理成一致状态才能恢复。MariaDB 用官方 `mariabackup`（XtraBackup 对 MariaDB 部分版本不兼容）。

### binlog 时间点恢复（PITR）

**场景**：昨天凌晨的全量备份 + 今天误删了一张表。先恢复全量，再重放全量位点之后、误删之前的 binlog，把数据追到误删前一刻：

```bash
mysqlbinlog --start-position=156 --stop-datetime="2026-09-27 10:00:00" \
  binlog.000002 | mysql -u root -p
```

### 备份策略

**定期全量（每日/每周）+ 持续保留 binlog**，用 crontab 自动执行、备份异地存放、**定期做恢复演练**。三者缺一，备份都可能在真出事时掉链子。

## 场景二 · 读写分离与分库分表

**为什么需要**：单机容量和连接数到顶后，读压力靠"写主读从"分摊，数据量靠"分库分表"水平扩展。

| 切分 | 说明 |
|---|---|
| 垂直分库 | 按业务拆库（用户库、订单库） |
| 垂直分表 | 把不常用/大字段拆到扩展表 |
| 水平分库/分表 | 按分片键（用户 ID 取模/范围）把同表数据分散 |

水平切分会带来一堆新问题：跨库 JOIN、分布式事务、全局唯一 ID（雪花/号段）、跨库排序分页、扩容迁移。**不是越大越好，是单机真扛不住才上**。

中间件选型：

| 中间件 | 特点 |
|---|---|
| **ProxySQL** | 高性能代理，读写分离、查询路由、连接池、故障感知 |
| **ShardingSphere** | JDBC（嵌入）/ Proxy（独立），分库分表+读写分离，社区活跃 |
| MyCat | 老牌，社区已不活跃，新项目不建议 |

完整的"主从+读写分离"组合落地见 [部署方案](/deploy/) 与 [我的项目 · 项目架构](/projects/homelab)。

## 场景三 · 主从延迟排查

**现象**：从库 `Seconds_Behind_Master` 持续增大，读到旧数据。**根因**通常是从库 SQL 线程重放跟不上主库写入：

- **大事务**：主库一个事务改百万行，从库单线程重放半天 → 拆分大事务。
- **从库性能弱**：从库配置低、还在跑备份/报表 → 升配或错峰。
- **单线程重放**：开并行复制 `slave_parallel_workers`（基于 WRITESET/LOGICAL_CLOCK）。

先用 `SHOW SLAVE STATUS\G` 看 IO/SQL 线程是否都 Yes、延迟多少，再 `SHOW PROCESSLIST` 看从库在重放什么。
