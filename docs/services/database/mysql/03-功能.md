# MySQL 03 · 功能详解

> 四篇制：[01 理论](./01-理论) · [02 部署](./02-部署) · [03 功能](./03-功能) · [04 实战](./04-实战)
> 本篇是日常使用：SQL 怎么写、权限怎么管、执行计划怎么读、慢查询怎么查。原理见 [01 理论](./01-理论)，这里聚焦"怎么用、哪里容易错"。

## 一、日常命令（中文详解）

| 命令 | 作用 | 什么时候用 |
|---|---|---|
| `mysql -u root -p` | 登录客户端 | 日常操作入口 |
| `mysql -h 主机 -P 3306 -u 用户 -p` | 远程登录 | 连别的实例 |
| `mysql -e "SQL"` | 非交互执行一条 SQL | 脚本里跑 |
| `mysqladmin status` | 看运行状态/线程/慢查询数 | 快速体检 |
| `mysqladmin processlist` | 看当前连接 | 排查谁连着 |
| `mysqldumpslow -s t -t 10 慢日志` | 汇总慢查询 Top | 定位慢 SQL |

SQL 按用途分四类：**DDL**（CREATE/ALTER/DROP，定义结构）、**DML**（INSERT/UPDATE/DELETE，改数据）、**DQL**（SELECT，查）、**DCL**（GRANT/REVOKE，权限）。

## 二、库与表（DDL）

```sql
CREATE DATABASE IF NOT EXISTS appdb
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
USE appdb;

CREATE TABLE users (
    id      INT PRIMARY KEY AUTO_INCREMENT COMMENT '主键',
    name    VARCHAR(50) NOT NULL COMMENT '姓名',
    age     TINYINT UNSIGNED DEFAULT 0,
    email   VARCHAR(100) UNIQUE,
    dept_id INT,
    created DATETIME DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';

DESC users;                       -- 看表结构
SHOW CREATE TABLE users\G         -- 看完整建表语句
ALTER TABLE users ADD COLUMN phone VARCHAR(20) AFTER name;
ALTER TABLE users MODIFY age INT;
ALTER TABLE users DROP COLUMN phone;
```

字符集统一用 **utf8mb4**——MySQL 里的 `utf8` 其实是阉割版（最多 3 字节），存不了 emoji 和部分生僻字，utf8mb4 才是完整 Unicode。`\G` 把结果竖排显示，看宽表（如 SHOW SLAVE STATUS）时比横排清楚得多。

## 三、增删改（DML）

```sql
INSERT INTO users (name, age, dept_id) VALUES ('tom', 20, 1);
INSERT INTO users (name, age, dept_id) VALUES ('jack',22,1),('lily',25,2);  -- 批量更快
UPDATE users SET age = 21 WHERE id = 1;
DELETE FROM users WHERE id = 4;
```

::: danger UPDATE / DELETE 必须带 WHERE
不带 WHERE 会改/删**整张表**。生产操作前先 `SELECT` 确认范围：`SELECT * FROM users WHERE dept_id=1;` 看清会影响哪些行再动手。
`TRUNCATE TABLE users` 是 DDL：清空整表、不可回滚、自增归零，和逐行 DELETE 机制完全不同。
:::

## 四、查询（DQL）

```sql
SELECT name, age FROM users WHERE age BETWEEN 20 AND 25;
SELECT * FROM users WHERE dept_id IN (1,2) AND name LIKE '张%';
SELECT * FROM users WHERE email IS NULL;        -- 判空用 IS NULL，不能 = NULL
SELECT * FROM users ORDER BY age DESC LIMIT 20,10;  -- 跳过20取10（第3页）
SELECT DISTINCT dept_id FROM users;
```

**聚合与分组：**

```sql
SELECT dept_id, COUNT(*) AS cnt, AVG(age) AS avg_age
FROM users GROUP BY dept_id HAVING avg_age > 22;
```

`WHERE` 在**分组前**过滤行（不能用聚合别名），`HAVING` 在**分组后**过滤组（可以用聚合结果）——这是两者的本质区别。`COUNT(*)` 统计所有行，`COUNT(email)` 只统计 email 非空的行。

**联表查询：**

```sql
SELECT u.name, d.dept_name
FROM users u LEFT JOIN dept d ON u.dept_id = d.id;
```

| 连接 | 结果 |
|---|---|
| INNER JOIN | 两边都匹配的行（交集） |
| LEFT JOIN | 左表全部 + 右表匹配（无匹配补 NULL） |
| RIGHT JOIN | 右表全部 + 左表匹配 |

实际中 **LEFT JOIN 用得最多**（"以左表为主，带上右表信息"）。**子查询**是查询里嵌套查询：`WHERE dept_id IN (SELECT id FROM dept WHERE dept_name='运维')`。

## 五、常用函数

```sql
SELECT CONCAT(name,'-',age), SUBSTRING('hello',1,3), UPPER('abc'), TRIM('  x  ');
SELECT NOW(), DATE_FORMAT(NOW(),'%Y-%m-%d %H:%i:%s'), DATEDIFF('2026-12-31',NOW());
SELECT ROUND(3.567,2), IFNULL(email,'未填写');
SELECT CASE WHEN age>=30 THEN '中年' WHEN age>=18 THEN '青年' ELSE '未成年' END FROM users;
```

注意 MySQL 字符串下标**从 1 开始**（SUBSTRING('hello',1,3)='hel'），`LENGTH` 算字节、`CHAR_LENGTH` 算字符（中文不一样）。

## 六、数据类型选型

| 场景 | 选什么 | 为什么 |
|---|---|---|
| 整数 | 够用最小的（TINYINT/INT/BIGINT） | 越小越省空间越快 |
| **金额** | **DECIMAL(10,2)** | 定点数无误差；FLOAT/DOUBLE 有浮点误差，存钱会出错 |
| 定长字符串（手机号/MD5） | CHAR(n) | 定长存储 |
| 变长字符串 | VARCHAR(n) | 按实际长度存，最常用 |
| 长文本 | TEXT | 无需指定长度 |
| 时间 | DATETIME / TIMESTAMP | DATETIME 与时区无关范围大；TIMESTAMP 随时区转换、到 2038 |

核心原则：**够用就选最小的类型**，金额必用 DECIMAL，字符串统一 utf8mb4。

## 七、用户与权限

```sql
CREATE USER 'app'@'10.0.0.%' IDENTIFIED BY 'App@123';   -- 先建用户
GRANT SELECT, INSERT, UPDATE ON appdb.* TO 'app'@'10.0.0.%';  -- 再授权
SHOW GRANTS FOR 'app'@'10.0.0.%';
REVOKE DELETE ON appdb.* FROM 'app'@'10.0.0.%';
```

账号格式是 `'用户名'@'允许登录的主机'`，`%` 表示任意主机、`10.0.0.%` 表示某网段。MySQL 8.0 必须**先 CREATE USER 再 GRANT**（GRANT 不再自动建用户）。

::: tip 最小权限原则
应用账号只给业务必需的权限（通常 SELECT/INSERT/UPDATE，不给 DROP/GRANT），主机范围尽量精确，别图省事全用 `%` + ALL。权限范围 `*.*` 全局 / `appdb.*` 某库 / `appdb.users` 某表。
:::

## 八、视图、存储过程、触发器

- **视图 VIEW**：一条 SELECT 的虚拟表，本身不存数据，用于简化复杂查询、隐藏敏感列。`CREATE VIEW v AS SELECT ...;`
- **存储过程 PROCEDURE**：一组预编译 SQL，`CALL` 调用，支持 IN/OUT 参数。写时要用 `DELIMITER $$` 临时改结束符，避免体内的 `;` 被提前截断。
- **触发器 TRIGGER**：表发生 INSERT/UPDATE/DELETE 时自动执行（BEFORE/AFTER），`NEW` 是新行、`OLD` 是旧行，常用于审计。
- **事件 EVENT**：库内定时任务（类似 crontab），需 `SET GLOBAL event_scheduler=ON`。

```sql
DELIMITER $$
CREATE PROCEDURE p_count_dept(IN d_id INT, OUT cnt INT)
BEGIN
    SELECT COUNT(*) INTO cnt FROM users WHERE dept_id = d_id;
END$$
DELIMITER ;
CALL p_count_dept(1, @cnt); SELECT @cnt;
```

## 九、EXPLAIN 执行计划（慢查询的钥匙）

在 SELECT 前加 `EXPLAIN`，看优化器打算怎么执行。重点盯三列：

```sql
EXPLAIN SELECT * FROM users WHERE dept_id = 1;
```

- **type**（访问类型，从好到差）：`const`（主键等值）> `eq_ref` > `ref`（普通索引等值）> `range`（索引范围）> `index`（扫整棵索引树）> **`ALL`（全表扫描，必须优化）**。
- **key**：实际用的索引，`NULL` 就是没用上索引。
- **rows**：预估扫描行数，越大越差。
- **Extra**：`Using index`（覆盖索引，好）、**`Using filesort`**（额外排序，需优化）、**`Using temporary`**（用临时表，常见 group by，需优化）。

**索引失效的常见情形**：索引列上用函数/运算、隐式类型转换（字符串列传数字）、`LIKE '%xx'` 前导通配、联合索引不满足最左前缀、OR 连接的列无索引。看到 type=ALL 或 key=NULL，先对照这几条查。

## 十、慢查询定位

```sql
SET GLOBAL slow_query_log = ON;
SET GLOBAL long_query_time = 1;          -- 超 1 秒记录
SHOW VARIABLES LIKE 'slow_query_log_file';
```

```bash
mysqldumpslow -s t -t 10 /var/lib/mysql/*-slow.log   # -s t 按时间排序，-t 10 取 Top10
```

优化思路：EXPLAIN 定位 → 加/调索引、用覆盖索引 → 避免 `SELECT *` → 优化联表（小表驱动大表）→ 深分页用 `WHERE id > x LIMIT n` 代替 `LIMIT 100000,10`。

## 十一、日常运维排查

```sql
SHOW FULL PROCESSLIST;                          -- 谁连着、在跑什么
SHOW VARIABLES LIKE 'max_connections';
SHOW STATUS LIKE 'Threads_running';
SELECT * FROM information_schema.innodb_trx;    -- 当前事务（抓长事务）
SELECT * FROM sys.innodb_lock_waits;            -- 锁等待
SHOW ENGINE INNODB STATUS\G                     -- 死锁/引擎状态
```

| 现象 | 方向 |
|---|---|
| Too many connections | 调大 max_connections、查连接泄漏、应用用连接池 |
| 突然变慢 | 慢查询、锁等待、连接打满、IO/CPU、索引失效 |
| 业务卡住 | 长事务未提交、更新无索引锁全表（见 [01 · 锁](./01-理论)） |

OS 层配合 [top](/commands/system/top)、[iostat](/commands/storage/)、[ss](/commands/network/ss) 看资源与连接。
