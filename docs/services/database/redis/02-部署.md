## 方案一 · 单机安装

**环境**：Rocky Linux 9 / Ubuntu 24.04，放行 6379（生产只对应用网段开放，务必设密码）。

### 源码安装（推荐，版本新）

```bash
sudo dnf install -y gcc make tar        # Debian: build-essential
tar -xzf redis-7.4.2.tar.gz && cd redis-7.4.2
make && sudo make PREFIX=/usr/local/redis install
sudo mkdir -p /etc/redis && sudo cp redis.conf /etc/redis/redis.conf
sudo /usr/local/redis/bin/redis-server /etc/redis/redis.conf
```

发行版仓库的 Redis 往往偏旧，源码编译能拿到最新稳定版，这也是官方推荐方式。

### 包管理 / 容器

```bash
sudo apt install -y redis-server        # Debian
sudo dnf install -y redis               # RHEL（EPEL）

docker run -d --name redis -p 6379:6379 \
  -v /data/redis/redis.conf:/etc/redis/redis.conf \
  -v /data/redis:/data \
  redis:7.4.2 redis-server /etc/redis/redis.conf
```

### 核心配置 redis.conf

```conf
bind 0.0.0.0
port 6379
daemonize yes
requirepass '请替换为强密码'
dir /data/redis
maxmemory 512mb
maxmemory-policy allkeys-lru
# io-threads 2        # 6.x 网络 IO 线程
```

几个关键项的意义：`requirepass` 设密码（Redis 默认无密码，公网裸奔会被挖矿脚本秒攻）；`maxmemory` 限内存上限，配合 `maxmemory-policy` 决定满了怎么淘汰（见 [01 · 淘汰](./01-理论)）；`dir` 是持久化文件落盘目录，容器化要挂出来。

### 验证

```bash
redis-cli -h 10.0.0.13 -a '密码'
```

```text
PING                  # 期望 PONG
INFO server           # 看版本/运行状态
```

## 方案二 · 主从复制（读扩展 + 冗余）

一主多从，从库分担读、提供数据冗余。搭建极简单，从库一条命令：

```text
REPLICAOF 10.0.0.13 6379        # 从库执行，旧命令 SLAVEOF
# REPLICAOF NO ONE              # 断开关联、升为主
```

首次连接触发**全量同步**（主库 BGSAVE 生成 RDB 发给从库），之后**增量同步**（PSYNC 补发）。用 `INFO replication` 看 `role` 和 `master_link_status:up` 确认同步正常。主从切换需手动——要自动切换就上哨兵。

## 方案三 · 哨兵 Sentinel（自动高可用）

在主从之上部署一组哨兵（**奇数个，如 3 个**，便于投票），提供监控、通知、自动故障转移。

```conf
# sentinel.conf
port 26379
sentinel monitor mymaster 10.0.0.13 6379 2     # quorum=2：至少2个哨兵同意才算客观下线
sentinel auth-pass mymaster '密码'
sentinel down-after-milliseconds mymaster 5000
sentinel failover-timeout mymaster 60000
```

```bash
redis-sentinel /etc/sentinel.conf
```

**故障转移流程**（原理见 [01](./01-理论)）：主观下线 → 达 quorum 客观下线 → 哨兵选 leader → 选一个从提升新主 → 其他从指向新主 → 客户端经哨兵获取新主地址。

::: warning 客户端要连哨兵，不是写死主库 IP
哨兵切换后主库地址会变，客户端必须通过哨兵（`SENTINEL get-master-addr-by-name mymaster`）动态获取主地址，写死 IP 就失去高可用意义了。
:::

## 方案四 · Cluster 集群（高可用 + 水平扩容）

哨兵解决了高可用但容量仍在单主。Cluster 分片把数据分散到多主，**3 主 3 从**起步：

```bash
# 各节点配置 cluster-enabled yes、cluster-config-file nodes-7001.conf、cluster-node-timeout 5000
redis-cli --cluster create \
  10.0.0.13:7001 10.0.0.13:7002 10.0.0.13:7003 \
  10.0.0.13:7004 10.0.0.13:7005 10.0.0.13:7006 \
  --cluster-replicas 1 -a '密码'

redis-cli -c -p 7001          # -c 集群模式，自动重定向到正确的槽
```

```text
CLUSTER NODES                 # 看节点与槽分配
CLUSTER INFO                  # cluster_state:ok 表示正常
```

`--cluster-replicas 1` 表示每个主配 1 个从。`-c` 参数让客户端遇到 `MOVED` 重定向时自动跳到正确节点——不加它，跨槽命令会直接报错。

### 扩容运维

```bash
redis-cli --cluster add-node 10.0.0.13:7007 10.0.0.13:7001   # 加节点
redis-cli --cluster reshard 10.0.0.13:7001                   # 迁移槽（扩容核心）
redis-cli --cluster check 10.0.0.13:7001                     # 检查槽覆盖一致性
```

加节点只是加入集群，**还要 reshard 把一部分槽迁过去**它才真正分担数据。完整的 Redis 哨兵/集群组合落地见 [部署方案](/deploy/) 与 [我的项目](/projects/homelab)。
