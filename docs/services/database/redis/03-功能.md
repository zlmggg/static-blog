# Redis 03 · 功能详解

> 四篇制：[01 理论](./01-理论) · [02 部署](./02-部署) · [03 功能](./03-功能) · [04 实战](./04-实战)
> 本篇是日常使用：各类型命令怎么写、什么场景用哪个、运维怎么看状态。类型选型原理见 [01 理论](./01-理论)。

## 一、通用命令（中文详解）

```bash
redis-cli -h 10.0.0.13 -a '密码'      # 连接
```

```text
PING                          # 测活，返回 PONG
SELECT 0                      # 切换 db（默认 16 个，0~15）
DBSIZE                        # 当前 db 的 key 数
EXISTS k                      # 判断 key 是否存在
DEL k                         # 删除
EXPIRE k 60                   # 设 60 秒过期
TTL k                         # 看剩余存活时间（-1 永不过期，-2 已不存在）
TYPE k                        # 看 key 的类型
RENAME k k2                   # 改名
CONFIG GET maxmemory          # 看配置
INFO                          # 看全量运行状态
```

::: danger 生产禁用 KEYS *
`KEYS *` 会**一次性遍历所有 key**，Redis 命令单线程，这一遍历就把主线程卡住，线上直接卡顿。要遍历用 **`SCAN 0 MATCH user:* COUNT 100`**——它渐进式分批返回，不阻塞。同理 `FLUSHALL`/`FLUSHDB` 清空库也要慎之又慎。
:::

## 二、String：缓存 / 计数 / 锁

```text
SET name tom
GET name
SET code 100 EX 60            # 写入并设 60 秒过期（验证码常用）
SETNX lock 1                  # 不存在才设置（分布式锁基础）
INCR cnt                      # 自增 1（原子，计数器）
INCRBY cnt 5
MSET a 1 b 2                  # 批量设
MGET a b                      # 批量取
```

`INCR` 是原子的（单线程保证），做计数器不用加锁。`SET key val EX 秒 NX` 一条命令同时设值和过期，是分布式锁的正确加锁姿势（见 [04](./04-实战)）。

## 三、Hash：存对象

```text
HSET user:1 name tom age 20
HGET user:1 name
HGETALL user:1                # 取所有字段
HINCRBY user:1 age 1          # 单字段自增
HDEL user:1 age
```

存对象用 Hash 而不是把 JSON 塞 String，好处是**能单字段更新**（改年龄不用重写整个对象），也更省内存。

## 四、List：队列 / 时间线

```text
LPUSH msgs a b                # 左端插入
RPUSH msgs c                  # 右端插入
LRANGE msgs 0 -1              # 取全部（0 到 -1 表示首到尾）
LPOP msgs                     # 左端弹出
BLPOP msgs 10                 # 阻塞式弹出，最多等 10 秒（队列消费常用）
LLEN msgs
```

`BLPOP` 的阻塞特性让它天然适合做消息队列：消费者没消息时阻塞等待，有消息立刻拿到，不用轮询。

## 五、Set：去重 / 交并差

```text
SADD tags redis linux mysql
SMEMBERS tags                 # 所有成员
SISMEMBER tags redis          # 判断是否成员
SINTER s1 s2                  # 交集（共同好友）
SUNION s1 s2                  # 并集
SDIFF s1 s2                   # 差集
SRANDMEMBER tags 1            # 随机取（不删，抽奖）
SPOP tags                     # 随机弹出（删）
```

交并差集是 Set 的杀手锏：共同好友 = 两个用户好友集的交集，可能认识的人 = 差集。

## 六、ZSet：排行榜

```text
ZADD rank 90 tom 85 jack 100 lily
ZREVRANGE rank 0 2 WITHSCORES   # 分数前 3 名（降序）
ZRANGEBYSCORE rank 80 95        # 分数区间
ZINCRBY rank 5 tom              # 给 tom 加 5 分
ZRANK rank tom                  # tom 的排名
ZSCORE rank tom
```

ZSet 底层用**跳表 + 哈希表**，插入和按分数范围查询都是 O(logN)，天生适合排行榜——`ZINCRBY` 加分、`ZREVRANGE` 取 TopN，不用自己排序。

## 七、专用类型

| 类型 | 场景 | 命令 |
|---|---|---|
| Bitmap | 签到/在线状态（极省内存） | SETBIT / GETBIT / BITCOUNT / BITOP |
| HyperLogLog | 海量 UV 去重计数（约 0.81% 误差） | PFADD / PFCOUNT / PFMERGE |
| Stream | 消息队列（消费组/ACK） | XADD / XREAD / XGROUP / XACK |
| Geo | 附近的人/门店 | GEOADD / GEORADIUS / GEODIST |

Bitmap 用 1 个 bit 表示一个布尔状态，一亿用户签到状态只要约 12MB；HyperLogLog 用极小内存估算海量去重数，适合"大概多少 UV"这种允许误差的场景。

## 八、持久化与淘汰配置

```conf
# RDB
save 900 1
save 300 10
# AOF
appendonly yes
appendfsync everysec
aof-use-rdb-preamble yes        # 混合持久化
# 淘汰
maxmemory 512mb
maxmemory-policy allkeys-lru
```

```text
BGSAVE                        # 手动触发 RDB（后台）
BGREWRITEAOF                  # 手动触发 AOF 重写
CONFIG SET maxmemory-policy allkeys-lfu   # 运行时改配置
```

各策略含义见 [01 · 持久化与淘汰](./01-理论)。`CONFIG SET` 改的是运行时配置，重启会丢，要永久生效得同步写回 redis.conf（或 `CONFIG REWRITE`）。

## 九、事务与 Lua

```text
MULTI                         # 开启事务
SET a 1
SET b 2
EXEC                          # 顺序执行（DISCARD 放弃）
WATCH key                     # 乐观锁：被改动则事务失败
```

```bash
redis-cli -a '密码' EVAL "return redis.call('get', KEYS[1])" 1 mykey
```

Redis 事务**不支持回滚**，需要真正原子的多步操作用 **Lua**（整体原子执行）。释放分布式锁就用 Lua 保证"判断+删除"原子（见 [04](./04-实战)）。

## 十、运维状态

```text
INFO memory                   # 内存使用/碎片率
INFO replication              # 主从角色/同步状态
INFO stats                    # 命中/未命中、连接数
SLOWLOG GET 10                # 慢命令 Top10
CLIENT LIST                   # 当前客户端连接
```

缓存命中率 = `keyspace_hits / (keyspace_hits + keyspace_misses)`，偏低说明缓存没发挥作用。OS 层配合 [top](/commands/system/top)、[free](/commands/observe/) 看内存。
