# Elasticsearch 01 · 服务理论

> 四篇制：[01 理论](./01-理论) · [02 部署](./02-部署) · [03 功能](./03-功能) · [04 实战](./04-实战)
> 本篇讲 ES 作为搜索/分析引擎的原理。把它用在日志链路的整体方案见 [ELK](/services/observability/elk)，本篇聚焦 ES 本身的检索与集群机制。

## 一、它是什么：分布式搜索分析引擎

Elasticsearch（ES）是基于 **Lucene** 的分布式、近实时搜索分析引擎，数据以 JSON 文档存储。它解决的核心问题是**海量数据的全文检索与聚合分析**——商品搜索、日志检索、指标分析。

### 为什么不用数据库 LIKE

MySQL `LIKE '%关键词%'` 有三个致命问题：无法用索引（全表扫描）、不支持分词（搜"运维工程师"匹配不到"工程师运维"）、数据量大就慢。ES 靠**倒排索引**解决：

- **正排索引**：文档 ID → 内容（数据库的思路）。
- **倒排索引**：词 → 包含该词的文档 ID 列表。搜一个词直接定位文档，不用扫全表。

倒排索引像书后的"索引页"：查"分布式"直接翻到出现的页码，而不是从第一页读到最后。

### 分词

写入时把文本切成词（term）建倒排索引。英文按空格/标点切，中文要用专门分词器（如 **IK 分词器**，把"运维工程师"切成"运维""工程师"）。分词质量直接决定搜索召回，中文场景必装 IK。

## 二、集群与数据组织

| 概念 | 含义 |
|---|---|
| Cluster | 节点集合，靠集群名标识 |
| Node | 一台服务器，有角色（master/data/ingest/coordinating） |
| Index | 一类文档集合，类似库/表，名全小写 |
| Document | 一条 JSON 记录 |
| Shard | 索引拆分的主分片，水平扩展单位 |
| Replica | 主分片副本，高可用 + 读吞吐 |

### 节点角色

- **master**：管集群状态（建删索引、分片分配），生产建议 3 个专用 master 防脑裂。
- **data**：存数据、执行 CRUD/聚合，吃内存磁盘。
- **ingest**：写入前预处理管道。
- **coordinating**：接收请求、分发、合并结果（每个节点默认都有）。

小集群一个节点身兼数职，大集群按角色分离。

### 分片与副本

主分片数**创建后不能改**（副本可随时调），要提前规划。主分片和自身副本**不在同一节点**——节点挂了副本顶上。分片不是越多越好，每个分片有管理开销（Lucene 实例、内存），小索引 1 个主分片即可。

## 三、近实时：refresh 机制

ES 是**近实时**（NRT）而非实时：文档写入后默认约 1 秒可被搜到。流程：写入先进内存 buffer + translog（防丢）→ **refresh**（默认 1s）把 buffer 生成新 segment 进 OS cache，此时可搜 → **flush** 把 segment 落盘、清 translog。

理解 refresh 就知道：为什么刚写入立刻搜可能搜不到（还没 refresh）；为什么频繁 refresh 影响写入性能（生成大量小 segment）。

## 四、文档与 mapping

mapping 定义索引的字段类型（text 会分词、keyword 不分词精确匹配、date、long、nested…）。**text 用于全文检索，keyword 用于精确过滤/聚合/排序**——一个字段常同时建 text + keyword 子字段。mapping 建错（如把状态码建成 text）会导致聚合报错，详见 [03 功能](./03-功能)。
