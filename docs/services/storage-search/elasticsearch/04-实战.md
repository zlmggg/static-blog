## 场景一 · 集群健康 yellow / red

```bash
curl -k -u elastic:密码 'https://10.0.0.61:9200/_cluster/health?pretty'
curl -k -u elastic:密码 'https://10.0.0.61:9200/_cat/shards?v'      # 看分片分布
curl -k -u elastic:密码 'https://10.0.0.61:9200/_cluster/allocation/explain?pretty'  # 分片为啥没分配
```

- **green**：主分片 + 副本都正常。
- **yellow**：主分片正常，**副本没分配**（单节点集群必然 yellow，因为副本不能和主同节点）。单节点设 `number_of_replicas: 0` 即 green。
- **red**：**有主分片没分配**，部分数据不可用，要紧急处理（节点挂了/磁盘满）。

`allocation/explain` 直接告诉你分片为什么没分配，是排障第一命令。

## 场景二 · 磁盘三级水位

ES 默认磁盘水位：85% 停止往该节点分配新分片、90% 尝试把分片迁走、95% 索引置只读（`read_only_allow_delete`）。日志堆满磁盘是 ES 最常见事故。

```bash
# 解除只读（清出空间后）
curl -k -u elastic:密码 -XPUT 'https://10.0.0.61:9200/_all/_settings' \
  -H 'Content-Type: application/json' -d '{"index.blocks.read_only_allow_delete": null}'
```

根治靠 ILM 自动删旧索引 + 扩容，别等写满。

## 场景三 · 索引生命周期 ILM

日志/时序索引按天滚动，用 ILM 自动管理热温冷删：

```json
PUT _ilm/policy/logs_policy
{ "policy": { "phases": {
  "hot":  { "actions": { "rollover": { "max_age": "1d", "max_size": "50gb" } } },
  "warm": { "min_age": "7d", "actions": { "shrink": { "number_of_shards": 1 } } },
  "delete": { "min_age": "30d", "actions": { "delete": {} } }
} } }
```

hot 写入滚动 → warm 缩分片省资源 → 30 天后 delete。别让索引无限堆。

## 场景四 · 分片规划与慢查询

- **分片规划**：单分片建议 10～50GB，分片数 ≈ 数据总量 / 单分片大小。分片过多（每个都是 Lucene 实例）吃内存拖慢集群，小索引 1 主分片足够。
- **慢查询**：开 slowlog 定位；深分页用 search_after（见 [03](./03-功能)）；聚合字段必须 keyword；避免 wildcard 前缀通配（`*xxx` 扫全索引）。

## 常见坑 FAQ

| 现象 | 原因 | 解法 |
|---|---|---|
| 启动报 max_map_count | 内核参数没调 | vm.max_map_count=262144 |
| 单节点 yellow | 副本没节点放 | 副本数设 0 |
| red 数据不可用 | 主分片没分配 | allocation/explain 查因 |
| 索引只读 | 磁盘超 95% 水位 | 清空间 + 解除 read_only |
| 聚合报错 fielddata | text 字段聚合 | 改用 keyword 子字段 |
| 脑裂选出两个 master | 偶数 master/网络分区 | 3 专用 master + 移除 initial_master_nodes |
| GC 停顿长 | 堆超 31G/开了 swap | 堆 ≤31G 且 ≤物理一半、关 swap |

OS 层排查：[df](/commands/storage/df) 看磁盘、[top](/commands/system/top) 看内存。更多见 [排障训练场](/cases/)。
